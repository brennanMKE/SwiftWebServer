# 0017 — If-Modified-Since never returns 304 because modification dates have sub-second precision

| | |
|---|---|
| **Status** | open |
| **Module** | Semantics |
| **Platform** | macOS |
| **First seen** | 2026-09-12 |

## Description

A conditional GET that sends back the exact `Last-Modified` value still gets 200. File modification dates carry sub-second precision, while the parsed `If-Modified-Since` date has whole seconds, so `modDate <= sinceDate` (`HTTPServer.swift:248`) is false. Verified on 2026-09-12.

## Steps to reproduce

1. `LM=$(curl -sI http://localhost:8080/index.html | grep -i last-modified | cut -d' ' -f2- | tr -d '\r')`
2. `curl -si http://localhost:8080/index.html -H "If-Modified-Since: $LM" | head -1`

## Expected behavior

`HTTP/1.1 304 Not Modified`

## Actual behavior

`HTTP/1.1 200 OK`

## Notes

Truncate `modDate` to whole seconds before comparing. Accept all three HTTP-date formats (RFC 9110 §5.6.7). Create the date formatter once (see #0025).
