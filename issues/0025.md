# 0025 — Every request reads the whole file into memory and hashes it with SHA-256

| | |
|---|---|
| **Status** | open |
| **Module** | StaticFiles |
| **Platform** | macOS |
| **First seen** | 2026-09-12 |

## Description

For every GET, `respond(to:)` loads the entire file with `Data(contentsOf:)` (`HTTPServer.swift:212`), runs SHA-256 over all of it to build an ETag (`HTTPServer.swift:282-301`), creates a new `DateFormatter`, and calls `fileExists` twice. Large files such as video cost their full size in memory and CPU on every request, even for requests that end in 304.

## Expected behavior

Validators are computed from metadata (size, modification time, inode) or cached per path and modification date, and bodies are streamed in chunks.

## Actual behavior

Full read and full hash on every request.

## Notes

#0032 covers streaming bodies. There is no `Range`/`206` support, which is worth tracking separately if needed.
