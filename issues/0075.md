## Description

The legacy parser builds `String`s, splits with `components(separatedBy:)`, has no "need more bytes" result and accepts incomplete data as complete (#0006). Write a hand-written, incremental `HTTP1Parser` that parses request heads directly from `ByteBuffer`, enforces limits, and is checked against a slow reference parser.

## Scope

- `HTTP1Parser` value-type state machine: `mutating func parseHead(_ buffer: inout ByteBuffer) -> ParseResult` returning `.complete`, `.needMoreBytes` or an error; resumes correctly when the head is split at any byte offset.
- Request line (method by word compare, request target, `HTTP/1.0` / `HTTP/1.1`), header fields into `HTTPFieldsView` with name scan + FNV-1a in one pass, obs-fold and bare-LF rejection, whitespace-before-colon rejection, token-table validation of names and field-value validation.
- Framing decisions per RFC 9112 §6: `Transfer-Encoding` chunked last wins over `Content-Length`; both present → reject; differing duplicate `Content-Length` → 400 (#0021); unknown transfer coding → 501.
- Limits from configuration with ROADMAP defaults: request line length, header count, total head size. Exceeding the head limit yields 431 (#0011 part); request line too long yields 414.
- Percent-decoding is not done here; the path stays a byte range (decode once, in #0084).
- Reference parser in `HTTPTestSupport`: obviously-correct, fully bounds-checked, slow; differential test feeds both parsers the same corpus (valid requests, the legacy bug repro requests from #0006/#0011, and generated mutations) and asserts identical results.
- The state-machine shape required by #0033 for the head parser (the connection-level part of #0033 is #0080).

## Acceptance criteria

- `swift test --filter HTTP1Tests` shows: every corpus request parsed identically when split at every byte offset (1-byte feeding included); #0006 repro (incomplete head) returns `.needMoreBytes`; an oversized head returns the 431 error; the differential test runs ≥ 10,000 generated inputs with zero mismatches.
- `sws-bench parse` records ns/request for a typical 10-header browser request: target < 150 ns, 0 allocations in our code; numbers committed to `docs/benchmarks/`.
