## Description

The legacy parser builds `String`s, splits with `components(separatedBy:)`, has no "need more bytes" result and accepts incomplete data as complete (#0006). Write a hand-written, incremental `HTTP1Parser` that parses request heads directly from `ByteBuffer`, enforces limits, and is checked against a slow reference parser.

## Scope

- `HTTP1Parser` value-type state machine: `mutating func parseHead(_ buffer: inout ByteBuffer) -> ParseResult` returning `.complete`, `.needMoreBytes` or an error; resumes correctly when the head is split at any byte offset.
- Request line (method by word compare, request target, `HTTP/1.0` / `HTTP/1.1`), header fields into `HTTPFieldsView` with name scan + FNV-1a in one pass, obs-fold and bare-LF rejection, whitespace-before-colon rejection, token-table validation of names and field-value validation.
- Framing decisions per RFC 9112 §6: `Transfer-Encoding` chunked last wins over `Content-Length`; both present → reject; differing duplicate `Content-Length` → 400 (#0021); unknown transfer coding → 501.
- Limits from configuration with ROADMAP defaults: request line length, header count, total head size. Exceeding the head limit yields 431 (#0011 part); request line too long yields 414.
- Percent-decoding is not done here; the path stays a byte range (decode once, in #0084).
- Reference parser in `HTTPTestSupport`: obviously-correct, fully bounds-checked, slow; differential test feeds both parsers the same corpus (valid requests, the legacy bug repro requests from #0006/#0011, and generated mutations) and asserts identical results.
- The state-machine shape required by #0033 for the head parser (the connection-level part of #0033 is #0080).

## Acceptance criteria

- `swift test --filter HTTP1Tests` shows: every corpus request parsed identically when split at every byte offset (1-byte feeding included); #0006 repro (incomplete head) returns `.needMoreBytes`; an oversized head returns the 431 error; the differential test runs ≥ 10,000 generated inputs with zero mismatches.
- `sws-bench parse` records ns/request for a typical 10-header browser request: target < 150 ns, 0 allocations in our code; numbers committed to `docs/benchmarks/`.

## Root cause

The legacy parser (`Legacy/HTTPRequest.swift`) builds `String`s, splits with `components(separatedBy:)`, has no "need more bytes" result, treats a request line as a complete request (#0006), enforces no head limit (#0011) and is not incremental (#0033). The new stack had no byte-level HTTP/1.1 head parser.

## Fix

- `HTTP1Parser` (`Sources/HTTP1/HTTP1Parser.swift`) is a value-type state machine with `mutating func parseHead(_ buffer: inout ByteBuffer) -> HTTP1ParseResult`, returning `.needMoreBytes`, `.complete` or `.error(HTTP1ParseError)`; each error maps to a status through `.status`. The parser keeps its scan offset and per-state progress between calls: token starts, the running FNV-1a hash, the query start and the host count. It never rescans, and any split of the input gives the same result. The reader index moves only on `.complete`, by `head.length`, so pipelined heads parse with repeated calls. Once the field index has grown, parsing allocates nothing and creates no `String`.
  - Header names: one loop checks each byte against `ASCII.tokenTable` (256 bits) and folds it into FNV-1a over the lowercased bytes. The loop ends at `:`, which is not a tchar, and `HTTPFieldName.lookup(hash:name:)` supplies the ID. Fields go into `HTTPFieldIndex`. `exchangeFields(with:)` and `parseHead(into: HTTPRequestStorage)` pass them to the request storage without copying, and `HTTP1RequestHead.request(in:)` builds the `HTTPRequest`.
  - Values: leading OWS is skipped. The value is scanned 8 bytes at a time with a SWAR test for any byte below 0x20 or DEL, using the bounds-checked `RawSpan.unsafeLoadUnaligned`. Trailing OWS is trimmed at the CR. NUL, DEL, other control bytes, bare CR and bare LF are rejected.
  - Request line:
    - Method: 1–24 tchars, matched by `HTTPMethod` word compare. A longer method gets 501.
    - Target: bytes 0x21–0x7E, classified at the SP that ends it. Origin-form; absolute-form (`scheme://authority[path][?query]`, no userinfo); authority-form (`host:port` with a 1–5 digit port), which is allowed only for CONNECT and required for it; asterisk-form (`*`), only for OPTIONS.
    - Path and query are `ByteView`s. `pathHasPercent` and `queryHasPercent` are set during the scan.
    - Version: `HTTP/1.0` or `HTTP/1.1`. Any other `HTTP/d.d` gets 505, and anything else gets 400.
    - Leading empty lines are skipped.
  - The first offending byte decides the error. A limit counts as an offending byte at the first position past it:
    - a request-line byte at offset `maxRequestLineLength` that is not CR or LF gets 414;
    - a field line beyond `maxHeaderCount` gets 431;
    - a byte at offset `maxHeadBytes` before the head ends gets 431.

    Defaults (`HTTP1ParserLimits`): 8 KiB request line, 100 fields, 16 KiB head.
  - After the head:
    - Host: HTTP/1.1 needs exactly one `Host`, and no version may have more than one (otherwise 400).
    - Framing (`HTTP1RequestFraming`: `.none`, `.contentLength(UInt64)`, `.chunked`) follows RFC 9112 §6.1 and §6.3. TE together with CL gets 400, and so does TE in HTTP/1.0. The TE codings must end in exactly one `chunked`, otherwise 400; any other coding before it gets 501.
    - CL is parsed by a digit loop when there is a single field, and by `HTTPFieldCollection.contentLength()` otherwise. Identical repeats are accepted; differing or invalid values get 400.
- `ReferenceHTTP1Parser` (`Sources/HTTPTestSupport/ReferenceHTTP1Parser.swift`) parses the whole input line by line over Latin-1 `String`s, using `Set`/`filter`/`split`-style checks, and shares no code with the fast parser. It models the head limit as "parse the prefix that fits, and turn need-more into 431". `HTTP1HeadOutcome` is the comparable outcome both parsers produce; errors compare by status.
- `sws-bench`: `parse.head 10-header browser request`, `parse.head minimal request` and `parse.head into HTTPRequestStorage`, in `Sources/sws-bench/ParserBench.swift`.

## Gotchas

- `HTTP1BodyFraming` is the serializer's response-side type (#0076). The parser's request-side framing type is `HTTP1RequestFraming`.
- The caller must not move the buffer's reader index or call `discardReadBytes()` while a head is in progress (`isInProgress`). The parser checks the reader index with a precondition. After `.error` the parser resets, and the connection answers with `error.status` and closes.
- Differential testing needs an exact positional rule for which error wins. Here the first offending byte wins, and a limit counts as the first byte past it. The 414 check skips CR and LF; without that, a bare LF exactly at the limit would get 414 from one parser and 400 from the other.
- On this shared machine, benchmark medians move by ±15% between runs, so run A/B builds back to back.
- Follow-ups for the 150 ns target, all outside HTTP1:
  - Make `HTTPFieldName.lookup(hash:name:)` cheaper. Each call goes through the global table accessor, the `canonicalName` switch and a closure-based compare.
  - Consider resolving names after the field section is scanned, so the per-field FNV-1a chains overlap.
