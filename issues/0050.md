## Description

Implement PING and the deprecated PRIORITY frame.

## Scope

- PING without ACK gets a PING ACK with the identical 8-octet payload, sent ahead of DATA. Unsolicited PING ACKs are ignored. PING on a non-zero stream is a `PROTOCOL_ERROR`.
- The server can send PINGs and await the matching ACK (used for RTT measurement and #0052).
- PRIORITY frames (§5.3.2 and §6.3) are parsed, length-validated, and otherwise ignored. A stream that depends on itself is a stream `PROTOCOL_ERROR`. The PRIORITY flag on HEADERS is parsed and ignored.
- `SETTINGS_NO_RFC7540_PRIORITIES = 1` is advertised (RFC 9218 §2.1).

## Acceptance criteria

- State machine tests for each rule.

## Root cause

Feature work. Earlier issues already covered part of this:

- the connection core (#0044) answers a PING with a PING ACK in the priority lane and ignores ACKs;
- the frame parser (#0035) checks the length of PRIORITY frames and rejects a PRIORITY frame whose stream depends on itself.

What was missing:

- the server could not send its own PING and wait for the ACK;
- a HEADERS frame whose PRIORITY flag made the stream depend on itself was served;
- SETTINGS did not advertise `SETTINGS_NO_RFC7540_PRIORITIES`.

## Fix

- **Server PINGs**
  - `HTTP2Connection` has two new events. `.sendPing(opaqueData:)` returns `.sendPing` and records the PING as outstanding (at most 4, with no duplicate data). `.pingAbandoned` forgets it.
  - An ACK whose data matches an outstanding PING becomes `.pingAcknowledged`. Any other ACK is ignored (§6.7).
  - `HTTP2ConnectionDriver.ping(timeout:)` sends a PING in the priority lane and waits for the ACK. It returns the round-trip time, or `nil` on a timeout, a closed connection or cancellation.
  - Waiters live in `HTTP2SharedState.pingWaiters` and are resumed outside the lock. Closing the connection, or a failed writer, resumes them with `false`.
- **PRIORITY** (RFC 9113 §5.3, §6.3)
  - PRIORITY frames are still parsed, length-checked (stream `FRAME_SIZE_ERROR`) and ignored. They are accepted on idle and closed streams without opening a stream.
  - A PRIORITY frame whose stream depends on itself is a stream `PROTOCOL_ERROR` (parser). The same check now applies to the PRIORITY flag on a HEADERS frame (driver, before dispatch).
  - Valid priority fields on HEADERS are ignored.
- `HTTP2Configuration.localSettings` sends `SETTINGS_NO_RFC7540_PRIORITIES = 1` (RFC 9218 §2.1).

## Verification

- `scripts/guarded.sh -t 900 -- swift test -j 2 --filter HTTP2Tests`: 181 tests passed. New in `H2PingPriorityTests` (13 tests, 14 cases):
  - state machine:
    - a PING is acknowledged with the same payload;
    - an unsolicited ACK is ignored;
    - a server PING is matched to its ACK, and an ACK with other data or a second ACK is ignored;
    - outstanding PINGs are bounded and an abandoned PING's ACK is ignored;
    - PRIORITY is ignored on idle, open, closed and never-opened streams, and does not open a stream;
    - a self-dependent PRIORITY becomes `RST_STREAM(PROTOCOL_ERROR)`;
  - parser: PING on a stream is a connection error; PRIORITY of 4 or 6 bytes is a stream `FRAME_SIZE_ERROR`;
  - SETTINGS carry `noRFC7540Priorities`;
  - over a connection:
    - PRIORITY on an idle stream, and a prioritized HEADERS, are served;
    - a self-dependent HEADERS and a self-dependent PRIORITY are each `RST_STREAM(PROTOCOL_ERROR)`;
    - a 4-byte PRIORITY is `RST_STREAM(FRAME_SIZE_ERROR)`;
    - the next request is served;
  - `pingAckOvertakesQueuedData`: with the writer held, a PING ACK goes out ahead of a 30 KB response queued before it;
  - `serverPingMeasuresTheRoundTrip` and `unansweredPingTimesOut`: these drive `HTTP2ConnectionDriver` directly through the new `withH2Driver` helper.

## Gotchas

- A stream error on an idle stream, such as a bad PRIORITY frame on a stream never opened, is still answered with RST_STREAM. RFC 9113 §6.4 says RST_STREAM must not be sent for an idle stream. h2spec (#0061) will show whether that matters.
- Our own PINGs are not counted as reply control frames for the flood limit (#0056), because the server decides when to send them.
