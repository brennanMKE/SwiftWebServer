# 0026 — Project docs claim Linux support and behaviors the server does not have

| | |
|---|---|
| **Status** | open |
| **Module** | Docs |
| **Platform** | macOS |
| **First seen** | 2026-09-12 |

## Description

The documentation disagrees with the code in several places:

- `PROJECT.md` says the server is "compatible with macOS and Linux", but it depends on Network.framework, CryptoKit, and os.log, which are Apple-only.
- `PROJECT.md` says it "Accepts a custom path via command-line argument" (`./webserver [directory]`), but the root comes from the `ROOT_PATH` environment variable.
- `PROJECT.md` says it sets `Connection: close` (see #0020).
- `PROJECT.md` documents `"caching": { "enable": true }`, but the key is `enabled` (see #0023).
- `TODO.md` lists HEAD as implemented (see #0016).
- `build.sh` builds `--product webserver`, which does not exist (the product is `SwiftWebServer`).
- `commands.txt` references a `SwiftWebServerFunctionalTests` target that does not exist.

## Expected behavior

The docs and scripts match the code.

## Notes

Link `HTTP2.md` from `PROJECT.md` while updating.
