# 0026 — Project docs claim Linux support and behaviors the server does not have

| | |
|---|---|
| **Status** | open |
| **Module** | Docs |
| **Platform** | macOS |
| **First seen** | 2026-09-12 |

## Description

The documentation disagrees with the code in several places:

- `docs/PROJECT.md` says the server is "compatible with macOS and Linux", but it depends on Network.framework, CryptoKit, and os.log, which are Apple-only.
- `docs/PROJECT.md` says it "Accepts a custom path via command-line argument" (`./webserver [directory]`), but the root comes from the `ROOT_PATH` environment variable.
- `docs/PROJECT.md` says it sets `Connection: close` (see #0020).
- `docs/PROJECT.md` documents `"caching": { "enable": true }`, but the key is `enabled` (see #0023).
- `docs/TODO.md` lists HEAD as implemented (see #0016).
- `scripts/build.sh` builds `--product webserver`, which does not exist (the product is `SwiftWebServer`).
- `scripts/commands.txt` references a `SwiftWebServerFunctionalTests` target that does not exist.

## Expected behavior

The docs and scripts match the code.

## Notes

Link `docs/HTTP2.md` from `docs/PROJECT.md` while updating.
