# 0106 — QPACK dynamic table support improves header compression (optional)

| | |
|---|---|
| **Status** | open |
| **Module** | QPACK |
| **Platform** | macOS |
| **First seen** | 2026-11-11 |

## Description

Optional: a dynamic table reduces header bytes for repeated requests. Only worth doing if `sws-bench` shows header bytes matter; it introduces shared mutable state and blocked streams.

## Scope

- Decoder side first: advertise a non-zero `QPACK_MAX_TABLE_CAPACITY` and `QPACK_BLOCKED_STREAMS`; process encoder-stream inserts, duplicates and capacity changes; Section Acknowledgment, Stream Cancellation and Insert Count Increment on the decoder stream; blocked streams bounded.
- Encoder-side dynamic insertion optional and separately configurable.
- Shared table state behind a `Mutex` with non-suspending critical sections (ROADMAP §2), off when disabled so the static path is unchanged.
- Table storage as a ring over one byte arena (ROADMAP §7).

## Acceptance criteria

- RFC 9204 Appendix B.2–B.5 examples decode with the expected table state after each step.
- `sws-bench` shows no change (< 2%) to the static-only path when the dynamic table is disabled.
