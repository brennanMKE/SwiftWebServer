## Description

Optional: a dynamic table reduces header bytes for repeated requests. Only worth doing if `sws-bench` shows header bytes matter; it introduces shared mutable state and blocked streams.

## Scope

- Decoder side first: advertise a non-zero `QPACK_MAX_TABLE_CAPACITY` and `QPACK_BLOCKED_STREAMS`; process encoder-stream inserts, duplicates and capacity changes; Section Acknowledgment, Stream Cancellation and Insert Count Increment on the decoder stream; blocked streams bounded.
- Encoder-side dynamic insertion optional and separately configurable.
- Shared table state behind a `Mutex` with non-suspending critical sections (ROADMAP §2), off when disabled so the static path is unchanged.
- Table storage as a ring over one byte arena (ROADMAP §7).

## Acceptance criteria

- RFC 9204 Appendix B.2–B.5 examples decode with the expected table state after each step.
- `sws-bench` shows no change (< 2%) to the static-only path when the dynamic table is disabled.

- **Milestone:** M10 — HTTP/3 hardening (optional)

## Root cause

HTTP/3 advertised `SETTINGS_QPACK_MAX_TABLE_CAPACITY = 0`, so peers could only send static-table and literal field lines. There was no dynamic table, no encoder-stream processing beyond the capacity-0 no-op, and no decoder-stream output.

## Fix

- `QPACKDynamicTable` (QPACK): a ring of entry records over one `QPACKByteArena` of `2 × maxCapacity` bytes, sized once, so inserts, evictions and capacity changes do not allocate. It is addressed by absolute index. An insert that names an entry it evicts moves the name with memmove first.
- `QPACKDynamicDecoder` (QPACK), a value type with no I/O:
  - Applies the encoder stream: Set Dynamic Table Capacity, Insert With Name Reference (static or dynamic), Insert With Literal Name, Duplicate. Errors are `QPACK_ENCODER_STREAM_ERROR`: capacity above ours, an entry larger than the capacity, a bad index, a string longer than any insert could be, or invalid Huffman.
  - Decodes Required Insert Count (§4.5.1.1) and Base with relative and post-Base indices. A reference that was evicted or is at or above the RIC, a RIC larger than needed, and a negative Base are all `QPACK_DECOMPRESSION_FAILED`.
  - `admit` counts blocked streams. One more than `SETTINGS_QPACK_BLOCKED_STREAMS` is `QPACK_DECOMPRESSION_FAILED`.
  - Queues Section Acknowledgment and Stream Cancellation. `takeDecoderStreamOutput` adds an Insert Count Increment for inserts the encoder has not been told about.
  - The `QPACKSectionDecoder` protocol lets `H3RequestHeadDecoder` take either decoder (generic, specialized in-module).
- HTTP3:
  - `H3Configuration.qpackMaxTableCapacity` and `qpackBlockedStreams` both default to 0. That keeps SETTINGS and the static-only path as before: no shared state and no extra lock. Off by default because it adds connection-shared state and blocked streams; turning it on is a configuration choice.
  - When the capacity is non-zero, the driver holds an `H3QPACKDecoderContext`: the decoder in a `Mutex`, with every critical section non-suspending.
  - The encoder-stream reader applies instructions and resumes blocked request streams (continuations, resumed outside the lock).
  - A request whose section is ahead of the inserts waits in `waitForInserts`. The wait counts against the header timeout. On cancellation it queues a Stream Cancellation, which the stream's (uncancelled) parent task sends.
  - Decoder-stream bytes are sent by whichever task claims the flush, in order, with no writer task. The flush waits until our decoder stream's type byte has gone out.
  - A decoder-stream backlog over 64 KiB (the peer does not read it) is `H3_EXCESSIVE_LOAD`.
  - `H3ConnectionTracker.qpackDynamicInserts` / `qpackDynamicSections` are debug counters.
- Encoder-side insertion was not done: responses stay static-table.

## Gotchas

- Do not send on the decoder stream from a cancelled task. The in-memory (and QUIC) send fails, and bytes already taken from the queue would be lost. `flushQPACKDecoderStream` returns early when cancelled, and `serveRequest` flushes after the stream's tasks end.
- The RFC's B.4 decoder cancels stream 8. Ours decodes it, so the test checks the acknowledgment (`88`) and then a separate cancellation (`48`).
- Decoding a dynamic section holds the connection's QPACK lock while the sink copies fields into the request storage. That is non-suspending but serializes head decoding across streams on one connection.
- Follow-ups:
  - Config-file wiring (`ServerSettings`/`ConfigFile`) for the two options was left out: another worker owns `Sources/ConfigFile`.
  - Encoder-side dynamic insertion for responses.
  - Deciding whether to turn the table on by default after interop testing with browsers.
