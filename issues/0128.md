# 0128 — Proxy timeouts can't be turned off: 0 or null keeps the default

| | |
|---|---|
| **Status** | open |
| **Module** | ConfigFile / Proxy |
| **Platform** | macOS |
| **First seen** | 2026-11-12 |

## Description

Found while writing the config reference. In `proxy[].timeouts`, setting `connect`, `response` or `idle` to `0` or `null` keeps the default instead of disabling that limit; only `total` is off by default. A long-polling or streaming upstream (server-sent events, long downloads) needs `idle`/`response` off or very large.

## Scope

- Define and implement: `0` (or `null`) disables that timeout, consistently for all four keys; document it in `docs/guide/running-on-a-mac.md` and the README.
- Keep a sane upper bound on values.

## Acceptance criteria

- ConfigFile tests for 0/null/positive on each key; a proxy test where `idle: 0` lets a slow-streaming upstream finish.
