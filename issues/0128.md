## Description

Found while writing the config reference. In `proxy[].timeouts`, setting `connect`, `response` or `idle` to `0` or `null` keeps the default instead of disabling that limit; only `total` is off by default. A long-polling or streaming upstream (server-sent events, long downloads) needs `idle`/`response` off or very large.

## Scope

- Define and implement: `0` (or `null`) disables that timeout, consistently for all four keys; document it in `docs/guide/running-on-a-mac.md` and the README.
- Keep a sane upper bound on values.

## Acceptance criteria

- ConfigFile tests for 0/null/positive on each key; a proxy test where `idle: 0` lets a slow-streaming upstream finish.

## Relation

- **Milestone:** M17 follow-ups (deployment readiness)
- **Blocked by:** none
- **Blocks:** none

## Root cause

`Parser.seconds` returns `nil` for both `0` and `null`, and `ProxySettings.Timeouts` used `nil` to mean "key absent", so `ProxySettings.policy` replaced an explicit off with the `UpstreamTimeouts` default (10 s connect, 60 s response, 60 s idle). Only `total` worked, because its default is already off.

## Fix

`ProxySettings.Timeouts.off` (`Duration.zero`) records an explicit `0`/`null`; an absent key stays `nil`. `policy` resolves absent → default, off → `nil` (no limit), anything else → the value, identically for all four keys. `timeouts.idle: 0` sets `tunnelIdleTimeout = .zero`, which `ReverseProxy+Upgrade` now reads as "no tunnel idle limit". Values stay capped at one year by `seconds`.
