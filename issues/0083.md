# 0083 — Middleware result builder, RequestContext and component registration compose an optional feature chain

## Description

Features must be opt-in components that cost nothing when absent (ROADMAP §1.1). `docs/MIDDLEWARE.md` stopped at "the interface needs to be defined" and #0031 proposed one handler. Build the middleware chain as a nested generic from a result builder, plus the per-request context and server-level component registration.

## Scope

- `@MiddlewareBuilder` producing a nested generic chain ending in a handler; `if`/`if-else` support for configuration-driven components; static dispatch through the chain (no existentials).
- `RequestContext`: connection info, request start time, a small typed storage for components (e.g. auth principal, virtual host), and a per-connection metrics shard.
- `ServerComponent.run(server:)` registration for components with background work (e.g. metrics scraping); components started inside the server task group.
- Wire `enableCompression`/`enableETags`-style flags to component registration (#0024 part).
- `HTTPHandler` dispatch from parts of #0031.

## Acceptance criteria

- Tests: a chain of three middlewares runs in order and can short-circuit; a conditional component absent from the chain is not called.
- `sws-bench` shows no measurable difference (< 2%) between an empty chain and a chain with a disabled conditional component.
