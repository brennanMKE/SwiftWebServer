## Description

HPACK (RFC 7541) and QPACK (RFC 9204) share N-bit prefix integers, string literals and the same static Huffman code. Implement them once in the `HeaderCompression` target. This moves #0037 and #0038 earlier and out of `HPACK`.

## Scope

- N-bit prefix integer encode/decode (RFC 7541 §5.1) with overflow protection and a configurable maximum.
- String literal encode/decode with the H bit selecting Huffman or raw (§5.2), reading from and writing to `ByteBuffer`.
- Table-driven Huffman decoder (multi-bit state table generated once, stored as a static array; unsafe pointers only here and in `ByteBuffer` per ROADMAP §7) that rejects padding over 7 bits, padding that is not EOS-prefix ones, and EOS in the data.
- Huffman encoder over the 257-symbol table with an encoded-length function so callers choose Huffman only when shorter.
- Errors are a small typed error; HPACK maps it to `COMPRESSION_ERROR`, QPACK to `QPACK_DECOMPRESSION_FAILED`.

## Acceptance criteria

- RFC 7541 Appendix C.1 integer examples and every Huffman-coded string in Appendix C.4 and C.6 encode and decode byte-for-byte.
- Padding and EOS error cases throw.
- `sws-bench huffman` records ns/byte for decode and encode with 0 allocations into a preallocated buffer.

## Root cause

New work, not a bug: HPACK and QPACK both need N-bit prefix integers, H-bit string literals and the RFC 7541 Huffman code, and `HeaderCompression` was an empty placeholder.

## Fix

- `PrefixInteger` encodes/decodes 1–8 bit prefixes, keeping the flag bits above the prefix. `decode` returns `.value(_, consumed:)`, `.needsMoreData` or `.overflow`. The ceiling is 2^62−1 (QUIC); callers can pass a smaller `maxValue`, and `maxHPACKValue` (2^32−1) is provided. An encoding longer than nine continuation bytes is reported as overflow.
- `Huffman` uses the canonical RFC 7541 Appendix B table. `encodedLength` sums the code lengths, and the encoder writes through a 64-bit accumulator that flushes every 32 bits. The decoder steps one nibble at a time through a 256-state × 16 `[UInt32]` table, built once as a static `let` from the code tree. Each entry holds the next state, the emitted symbol and emit/EOS/accepting/ones-prefix flags, so the padding and EOS checks need no extra work per bit.
- `StringLiteral` handles the H flag at bit `prefixBits` (7 for HPACK, 3 or 5 for QPACK). The encoder's policy is `.whenShorter`, `.always` or `.never`. The decoder enforces a length limit and returns `.needsMoreData` without writing any output until the whole literal has arrived.
- `HeaderCompressionError` is one typed error with these cases: `endOfStringSymbol`, `paddingTooLong`, `invalidPadding`, `integerOverflow` and `stringTooLong`. HPACK maps it to `COMPRESSION_ERROR` and QPACK to `QPACK_DECOMPRESSION_FAILED`.
- Input is `UnsafeRawBufferPointer` and output is any `ByteSink`. `[UInt8]` conforms, and `ByteBuffer` can conform later. Unsafe buffer pointers appear only in the table lookups.

## Verification

- `scripts/guarded.sh -t 600 -- swift build`: build complete.
- `scripts/guarded.sh -t 600 -- swift test`: all targets pass. HeaderCompressionTests ran 26 tests in 4 suites: `PrefixIntegerTests`, `HuffmanTests`, `StringLiteralTests` and the module tests. They include `rfc7541C11/C12/C13`, `rfc7541AppendixC` (all 12 Huffman strings from C.4 and C.6, checked byte for byte in both directions), `codeTableIsTheCanonicalRFC7541Code`, `everySingleByteRoundTrips`, `seededRandomStringsRoundTrip` (2,000 SplitMix64 strings), `acceptsPaddingOfOneToSevenOnes`, `rejectsEOSSymbol`, `rejectsPaddingLongerThanSevenBits`, `rejectsPaddingThatIsNotAllOnes`, `rfc7541Literals` (C.3.1/C.4.1 `:authority`) and the prefix-integer overflow, `needsMoreData` and HPACK-bound tests.
- `swift run -c release sws-bench` was run with a temporary, uncommitted call in `main` on a 117-byte user-agent value. Decode measured 414 MB/s (2.41 ns/byte) and encode 342 MB/s (2.93 ns/byte). Both timed loops reuse one preallocated `[UInt8]`.

## Gotchas

- Swift 6.4.2 crashes during SILGen cleanup ("Illegal convention for non-address types") on a closure annotated `throws(HeaderCompressionError)` that is passed to `Array.withUnsafeBytes`. To avoid it, catch inside the closure and return the error, as the tests and `Huffman.decode` do.
- `Array.reserveCapacity(count + n)` allocates exactly what is asked for, so calling it on every append makes copying quadratic. `reserveAdditionalCapacity` grows the capacity at least 2×.
- The `sws-bench huffman` subcommand belongs to the harness `main`, which another worker owns. Only the functions exist here.
