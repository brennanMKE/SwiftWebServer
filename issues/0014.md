# 0014 — Path containment check uses a string prefix and does not resolve symlinks

| | |
|---|---|
| **Status** | open |
| **Module** | Security / StaticFiles |
| **Platform** | macOS |
| **First seen** | 2026-09-12 |

## Description

The traversal guard `fileURL.path.hasPrefix(runtimeConfig.publicURL.path)` (`HTTPServer.swift:198`) passes for sibling directories whose names start with the public directory's name. Symlinks inside `Public` that point outside it are followed.

## Steps to reproduce

1. `mkdir Root/PublicBackup && echo secret > Root/PublicBackup/secret.txt`
2. `curl --path-as-is http://localhost:8080/../PublicBackup/secret.txt`

## Expected behavior

403 Forbidden.

## Actual behavior

200 with `secret`. (`/../http-config.json` is correctly rejected because it does not share the prefix.)

## Notes

Compare resolved path components (`resolvingSymlinksInPath()` on both URLs, then check that the public URL's components are a prefix of the file's components), or append a trailing `/` to the root before the prefix check. Decide whether symlinks should be allowed at all.
