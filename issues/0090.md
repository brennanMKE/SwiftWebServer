## Description

The legacy server makes about 14 log calls per request (ROADMAP §3). Provide an opt-in AccessLog component and per-connection/per-stream metrics (#0064) that shard counters and merge them on close or scrape.

## Scope

- AccessLog middleware writing one line per request (common or JSON format) through `os.Logger` or a buffered file writer; formatting off the hot path where possible.
- Metrics: per-connection shard (requests, bytes in/out, status classes, latency histogram) merged into a server total on connection close or scrape (ROADMAP §7 "Shard, don't share"); per-stream counters exposed for HTTP/2 and HTTP/3 when those land.
- Optional `/metrics` endpoint (text format) behind configuration.

## Acceptance criteria

- Unit tests for line format and shard merging.
- `sws-bench` shows no change (< 2%) with the component unregistered versus a build without it; registered cost per request is recorded.

## Root cause

New feature. The legacy server logged about 14 times per request on the request path; the new
stack had no access log or metrics, and no place for a component to keep per-connection state
(the middleware value is shared by every connection, and a lookup table keyed by connection
would need a lock on every request).

## Fix

- **Extension point (HTTPCore, generic):** `ConnectionObserver` (`connectionWillStart(_:)`,
  `connectionDidEnd(_:)`), `ConnectionObservers` and `MiddlewareChainInspector.connectionObservers(in:)`.
  `ConnectionContext.requestContext` is the context every request on a connection starts from
  (`info` is now a view of it), so an observer sets a typed value once per connection and each
  request finds it in `context[Key.self]`. `Server` finds observers in the chain and in
  `components:` and calls them around each connection; the HTTP/1.1 and HTTP/3 runners start
  from `context.requestContext`. `BoundedAsyncQueue` gained `trySend` (never suspends) and
  `tryNext`.
- **`AccessLog` (target AccessLog):** one chain element that is an `HTTPMiddleware`, a
  `RequestStartTimeConsumer`, a `ConnectionObserver` and a `ServerComponent` (the writer).
  Formats Common, Combined or JSON-lines (method, path, query, status, bytes, duration, peer,
  protocol from ALPN, referer, user agent) straight into the connection's buffer, escaping
  hostile bytes (`\xHH` / RFC 8259 with U+FFFD for invalid UTF-8). Full batches go to the writer
  with `trySend`; a full queue drops the batch and counts its lines. The writer drains in 1 ms
  bursts, collects idle connections' lines every `flushInterval`, recycles written buffers, and
  on cancellation (after the last connection closed) writes everything queued or buffered.
  Destinations: file (`O_APPEND`), stdout, stderr, `os.Logger`, discard, handler. A destination
  that cannot be opened throws from `run(server:)`, which shuts the server down.
- **Metrics:** `AccessLogMetrics` with per-connection `MetricShard`s (relaxed atomic adds, no
  lock): responses by status class, request/response body bytes, a 25-bucket log-scale latency
  histogram (`(2^(k-1), 2^k]` µs, 1 µs to 8.4 s, plus overflow). Shards merge into the total on
  connection close; `snapshot()` adds the open ones. `MetricsEndpoint` (separate opt-in
  middleware) serves Prometheus text 0.0.4 at `/metrics`.
- **sws-bench:** `h1conn` rows `log-metrics`, `log-null`, `log-json`, `log-file`,
  `log-file-metrics` and matching `dispatch` rows; `serve --access-log PATH|-`,
  `--access-log-format common|combined|json`, `--metrics`.
- Docs: `docs/MIDDLEWARE.md` (connection observers, AccessLog as the reference component),
  `docs/benchmarks/M6-accesslog.md`.

## Gotchas

- Waking the writer per batch (`trySend` resuming a suspended consumer is a thread wake-up on
  the request path) and a `malloc` per batch freed on another thread cost about 16 ns per line
  at 8 KiB batches. The writer now sleeps 1 ms between bursts and recycles buffers; the queue
  must hold about a millisecond of peak output (default 1024 × 8 KiB).
- A struct holding a copy of the `HTTPRequest` costs two retains per line; pass the request
  alongside. A global per-request counter would bounce between cores; count per batch.
- `InlineArray` and `Array.span` need macOS 26; the shard keeps its atomics in one allocated
  block of `Atomic<UInt64>`.
- One `AccessLog` per chain: two share the context key and the inner one falls back to its
  shared, locked buffer.
- The line is recorded when the handler returns: duration is time to the response, and a
  stream without a length logs `-` bytes. Protocol comes from ALPN, so cleartext HTTP/1.0 logs
  as `HTTP/1.1`.
- Not done: per-stream counters for HTTP/2 and HTTP/3, and observers for the HTTP/3 runner
  (driven by `H3ServeCommand`, not `Server`; its requests use the log's shared buffer). The
  #0064 items (`os.Logger` categories, signposts, GOAWAY/reset counters) are not covered.
