## Description

One server should serve several sites selected by `Host`/`:authority`.

## Scope

- Host matching on the authority bytes (exact and `*.suffix` wildcard), port stripped, case-insensitive, no `String` on the hot path.
- Each host has its own chain (e.g. its own StaticFiles root); a default host or `421 Misdirected Request` when none matches.
- Host name stored in `RequestContext` for logging.

## Acceptance criteria

- `curl -H 'Host: a.test' ` and `curl -H 'Host: b.test'` against one port return different roots; an unknown host returns the default or 421 per configuration.
- `sws-bench` shows no change (< 2%) with the component unregistered.

## Relation

- **Milestone:** M6 — Small components

- **Supersedes:** none

## Root cause

New component: the `VirtualHosts` target was a placeholder namespace.

## Fix

- `VirtualHosts` (middleware and handler) holds `VirtualHost`s, each with its names and its own handler chain: `VirtualHost("a.test", "www.a.test", handler: StaticFiles(…))`, `VirtualHost("*.b.test") { … }` (`@MiddlewareBuilder`), `VirtualHost.default(…)`; a `@VirtualHostBuilder` collects them (`if`/`else`/`for`).
- The host is `:authority` (HTTP/2, HTTP/3, HTTP/1.1 absolute-form) or else `Host`; a trailing `:port` (`[v6]:port` keeps the brackets) and one trailing `.` are dropped; comparison is ASCII case-insensitive; punycode is matched as written (non-ASCII names are rejected at build time).
- `HostTable` compiles the names into two open-addressing tables (exact names, `*.suffix` wildcards stored as `.suffix`) keyed by FNV-1a of the lowercased bytes taken right to left, so one leftward pass gives the whole-name hash and every dot-suffix hash: exact beats any wildcard, the longest wildcard wins, `*.b.test` does not match `b.test`. No allocation, no `String`.
- No match: the default host, else `421 Misdirected Request` (`unmatched: .misdirected`) or `next` (`unmatched: .next`, `404` as a handler). HTTP/1.0 without `Host` takes the same path; HTTP/1.1 without `Host` is already `400` from the parser (`HTTP1Parser` `.missingHost`).
- Each host's chain is stored as a closure compiled with its types known (one indirect async call); `forEachChainElement` exposes the chains so the server finds components inside a host.
- `recordsHost: true` sets `MatchedVirtualHost` (index, first name, fallback flag) as `context.virtualHost`.
- Build errors (`VirtualHostsError`): empty, ports, misplaced `*`, empty labels, non-ASCII, bad IPv6 literal, duplicate names (after normalization), two defaults.
- ConfigFile: `"hosts": [{"names": [...], "root": "...", "default": true}]` (also `"name"`); each site is `StaticFiles` over its own root with the shared file settings, replacing the single root via `EitherHandler<VirtualHosts, StaticFiles>`. Names are validated at parse time; an unusable root names `hosts[i].root`. The executable prints one "serving" line per site.
- `sws-bench micro --filter VirtualHosts`.

## Gotchas

- Setting a `RequestContext` value allocates one node (#0094's note), so recording the matched host is opt-in (`recordsHost`, off by default, also off from the config): the issue asked for the host in the context, the lookup itself stays allocation-free. Turn it on when an access log needs the site.
- `StaticFiles` is both a middleware and a handler, so the config wires the terminal through an explicit `EitherHandler<VirtualHosts, StaticFiles>`; with `hosts` set the top-level `root` is never opened (it may not exist).
- The `<2%` "unregistered" criterion holds by construction (no change outside VirtualHosts, ConfigFile wiring, sws-bench); `h1conn` was not rerun because other agents were building.
