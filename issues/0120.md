# 0120 — Server cannot forward requests to an upstream app server because it has no HTTP/1.1 upstream client

| | |
|---|---|
| **Status** | open |
| **Module** | Proxy / NetworkTransport |
| **Platform** | macOS |
| **First seen** | 2026-11-11 |

## Description

There is no client side for talking to an upstream (backend) HTTP server. A reverse proxy needs an HTTP/1.1 client with a pool of keep-alive connections to upstreams on loopback TCP and on Unix domain sockets.

The owner's use case: run app servers (for example Go `net/http`) on localhost, with this server as the public TLS endpoint serving HTTP/1.1, HTTP/2 and HTTP/3. A static website is served at `/`, and a path prefix such as `/api` (or `/cgi-bin`) is reverse-proxied to a web app. The reference upstream is the Go app in `Examples/go-api` (Go 1.27 is installed). This is what Apache `mod_proxy` (`ProxyPass` / `ProxyPassReverse`) does today.

## Scope

- New `Proxy` target. The upstream client is built on the existing transports: a BSD-socket TCP connect, plus a new Unix-domain-socket connect in `NetworkTransport` that shares the kqueue event loop.
- Reuse the `HTTP1Serializer` to write requests and the parser machinery to read responses. Add response-side parsing (status line, headers, Content-Length, chunked and close-delimited bodies), as a sibling of `HTTP1Parser` that is split-invariant and has limits.
- Connection pool per upstream:
  - A bounded number of idle keep-alive connections.
  - A max number of connections, with the waiting queue bounded too.
  - Idle eviction.
  - Discard any connection the upstream closed or answered with `Connection: close`.
  - Never reuse a connection after a partial or failed exchange.
- Streaming both ways with backpressure. The request body is pulled from `HTTPRequestBody` as the upstream accepts it. The response body is handed to the downstream writer as `.stream`, so nothing is buffered whole.
- No allocation per request on the steady-state keep-alive path apart from what the response body needs.

## Acceptance criteria

- Unit tests against an in-memory upstream: keep-alive reuse, chunked and Content-Length responses, a close-delimited response, a malformed response, and an upstream close mid-body.
- Integration tests with a real upstream on 127.0.0.1:0 and on a Unix socket in `$TMPDIR`. The upstream is a small server in the test target (or `sws-bench serve`).
- `sws-bench micro`: added proxy overhead per request with a warm pool.
