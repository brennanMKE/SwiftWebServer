## Description

Found while writing the static-sites guide. When `hosts` is configured, ErrorPages resolves its files against the top-level `root`, not each host's root, so the top-level root directory must exist and each site can't have its own error pages.

## Scope

- Error pages resolve per host (host root first, then the top-level root as a fallback), or allow `hosts[].errorPages`.
- The top-level `root` need not exist when every request is served by a host.

## Acceptance criteria

- Tests: two hosts with different 404 pages; a config with `hosts` and no top-level root directory starts and serves.

## Relation

- **Milestone:** M17 follow-ups (deployment readiness)
- **Blocked by:** none
- **Blocks:** none

## Root cause

`makeHandler` built a single outer `ErrorPages(root: resolvedRoot, …)` for `errorPages` files whether or not `hosts` was set, so files resolved only against the top-level root (which then had to exist) and every site shared them.

## Fix

`ErrorPages.init(roots:pages:defaultPages:requireAll:)` looks each file up in several roots, first match wins, skipping roots that do not exist (`init(root:)` now delegates to it). With `hosts`, `makeVirtualHosts` puts an `ErrorPages` over `[site root, top-level root]` at the front of each site's chain (so proxied `502`/`504` get the site page too); a page in neither root fails startup naming `errorPages.NNN` and `hosts[i].root`. The outer layer (for `421` and auth rejections) uses the top-level files leniently (`requireAll: false`) or generated pages when that root is missing.
