# 0084 — StaticFiles serves files safely with metadata ETags, MIME types, 405 with Allow and Range requests

| | |
|---|---|

## Description

The legacy static file code has a block list that never matches (#0013), a string-prefix containment check that ignores symlinks (#0014), double percent-decoding (#0015), a 405 without `Allow` (#0022), reads and SHA-256-hashes the whole file per request (#0025), and buffers whole files (#0032). Rewrite it as the `StaticFiles` component.

## Scope

- Percent-decode the path exactly once, only if `%` is present (#0015); reject NUL, encoded `/` and `..` segments after decoding.
- Containment: resolve against the canonical root with `realpath`-equivalent resolution; symlink policy configurable (follow-within-root default, never escape) (#0014).
- Block list matched on normalized path segments (dotfiles and configured patterns) (#0013).
- MIME table, index file resolution, `405 Method Not Allowed` with `Allow: GET, HEAD` for other methods (#0022).
- ETag from size + mtime + inode, rendered without `String(format:)` (#0025); `Last-Modified` truncated to whole seconds.
- Small-file cache with pre-rendered headers; large files sent with `.file(FileRegion)` via bounded `pread` or an mmap region, never fully buffered (#0032).
- Single-range `Range: bytes=` requests → `206` with `Content-Range`; unsatisfiable → `416`; multi-range may answer 200.
- Static-file handler parts of #0031.

## Acceptance criteria

- Tests reproduce the steps of #0013, #0014, #0015, #0022 and #0025 against the new component and pass.
- `curl -r 0-99 http://localhost:<port>/<file>` returns 206 with 100 bytes; `curl -X POST` returns 405 with `Allow`.
- Serving a 1 GiB file with `curl -o /dev/null` keeps server RSS flat (within 32 MiB of idle, measured with `ps -o rss`).
- `oha` small-file throughput beats the legacy baseline from #0070.
