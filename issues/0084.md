## Description

The legacy static file code has a block list that never matches (#0013), a string-prefix containment check that ignores symlinks (#0014), double percent-decoding (#0015), a 405 without `Allow` (#0022), reads and SHA-256-hashes the whole file per request (#0025), and buffers whole files (#0032). Rewrite it as the `StaticFiles` component.

## Scope

- Percent-decode the path exactly once, only if `%` is present (#0015); reject NUL, encoded `/` and `..` segments after decoding.
- Containment: resolve against the canonical root with `realpath`-equivalent resolution; symlink policy configurable (follow-within-root default, never escape) (#0014).
- Block list matched on normalized path segments (dotfiles and configured patterns) (#0013).
- MIME table, index file resolution, `405 Method Not Allowed` with `Allow: GET, HEAD` for other methods (#0022).
- ETag from size + mtime + inode, rendered without `String(format:)` (#0025); `Last-Modified` truncated to whole seconds.
- Small-file cache with pre-rendered headers; large files sent with `.file(FileRegion)` via bounded `pread` or an mmap region, never fully buffered (#0032).
- Single-range `Range: bytes=` requests → `206` with `Content-Range`; unsatisfiable → `416`; multi-range may answer 200.
- Static-file handler parts of #0031.

## Acceptance criteria

- Tests reproduce the steps of #0013, #0014, #0015, #0022 and #0025 against the new component and pass.
- `curl -r 0-99 http://localhost:<port>/<file>` returns 206 with 100 bytes; `curl -X POST` returns 405 with `Allow`.
- Serving a 1 GiB file with `curl -o /dev/null` keeps server RSS flat (within 32 MiB of idle, measured with `ps -o rss`).
- `oha` small-file throughput beats the legacy baseline from #0070.

## Root cause

The legacy handler checked raw request paths against a block list of bare names with exact matching, decoded the path twice, checked containment with a string prefix and no symlink resolution, answered 405 without `Allow`, and on every GET read the whole file into memory and SHA-256-hashed it for a weak ETag.

## Fix

`StaticFiles` (target `StaticFiles`) conforms to `HTTPHandler` and to `HTTPMiddleware`. As middleware it falls through to `next` for other methods and for misses, and still answers 400 and 403 itself.

- `DecodedPath.decode`: a single pass that decodes `%XX` (a decoded `%` stays literal) and splits components. It rejects bad escapes, NUL, `\`, `%5C` and an encoded `/` (400), and `..` (403) after decoding. It drops empty and `.` components.
- Block list (#0013): blocked names are matched case-insensitively against every component of the decoded path and of the canonical path, so a symlink to `.git/config` is blocked too. Dotfiles are blocked by default, except `.well-known`. Configurable.
- `PathResolver` (#0014): the root is canonicalized once. `realpath` on root + decoded path, then the containment check is component-wise (`/srv/Public2` is not inside `/srv/Public`). `SymlinkPolicy` is `.followWithinRoot` (default), `.deny` (an `lstat` walk) or `.followAnywhere`.
- Directories without a trailing `/` get a 301. The `Location` is rebuilt from the normalized path, so `//host` can never become a scheme-relative redirect, and the query is kept. With the slash, `indexFiles` are tried (default `index.html`). There are no listings.
- `MIMETypes`: a static `(StaticString, StaticString)` table holding the legacy `http-config.json` types plus about 50 common ones. Lookup is case-insensitive with no allocation. Configurable overrides and default (`application/octet-stream`).
- GET and HEAD only. Everything else gets 405 with `Allow: GET, HEAD` (#0022).
- `CachedFile` (#0025, #0032): `open` + `fstat`, then the ETag `"<size-hex>-<mtime-ns-hex>-<inode-hex>"` and `Last-Modified` from the mtime seconds via `IMFFixdate`. The 200 response is rendered once: files up to 64 KiB as `.bytes` in memory, larger files as `.file(FileRegion)` over a descriptor the entry keeps open.
- `FileCache`: 16 `Mutex` shards keyed by FNV-1a-64 of the raw path, bounded (`maxCachedEntries`, default 1024, random eviction). An entry is re-checked with `realpath` + `stat` at most once per `revalidationInterval` (1 s), by one request while the others keep getting the cached entry. A hit allocates nothing and makes no system call: about 75 ns.
- Range: one `bytes=a-b`, `a-` or `-n` gets 206 with `Content-Range`, a small file's slice copied and a large file's served as an offset region. Unsatisfiable gets 416 `bytes */size`. Multiple ranges, other units and syntax errors get 200. HEAD ignores Range. If-Range must match the exact strong ETag or the exact Last-Modified.
- `sws-bench serve --root DIR`. `BSDSocketTransport.sendFile` uses non-blocking `sendfile(2)`: a partial send waits for writability, and `ENOTSUP` falls back to the `pread` loop.

## Gotchas

- Conditional requests (`If-None-Match`, `If-Modified-Since`, 304) are left to #0085. `CachedFile.etag` and `lastModified` hold the rendered validators for that work.
- Error responses (400, 403, 404, 405, 416) have empty bodies. Error pages are #0085.
- Within one revalidation interval a changed file is still served from the cache. An in-place rewrite of a cached large file can make a running `sendfile` stop short (`unexpectedEndOfFile`), and the connection is aborted.
- 404s are not cached, so every miss costs `realpath`.
- The cache key is the raw path, so `/a%62c` and `/abc` are separate entries for the same file.
