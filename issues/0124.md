## Description

Expose the reverse proxy through `http-config.json` so the shipped binary can replace an Apache `mod_proxy` front end, for example a static website at `/` with `/cgi-bin` (or `/api`) proxied to a Go app on localhost.

## Scope

- A `proxy` config key: a list of mounts, each with:
  - `path` (prefix, default `/`), optional `host`/`hosts`
  - `upstream` or `upstreams` (`http://127.0.0.1:9000[/base]` or `unix:/path/to.sock`)
  - `stripPrefix`, `preserveHost`, `forwardedHeaders` (`x-forwarded` | `forwarded` | `both` | `none`), `trustedProxies`
  - `rewriteLocation`, `websocket`, `timeouts`, `retries`, `healthCheck`, and `maxConnections` and pool settings
- Ordering in the chain: Auth, then the proxy mounts, then StaticFiles/ErrorPages. Mounts take precedence for their prefix and everything else falls through to the static site. Works per virtual host (`hosts[].proxy`).
- The example config already exists: `Root/http-config.proxy.json` serves static `Root/Public` at `/` and proxies `/api` to the Go app `Examples/go-api` on `127.0.0.1:9000` (`stripPrefix: false`, since the Go app serves `/api/...` itself). Until this milestone lands, the server warns that `proxy` is an unknown key and ignores it. Make the config work as written, or adjust it and the docs together. A README section "Reverse proxy (replacing Apache mod_proxy)" maps `ProxyPass`/`ProxyPassReverse`/`ProxyPreserveHost` and `RequestHeader set X-Forwarded-Proto` to the equivalent keys.
- Upstream for docs and tests: `Examples/go-api`, a stdlib-only Go REST API (`/api/health`, `/api/items` CRUD, and `/api/echo`, which returns the request as the app saw it, including the forwarded headers). Integration tests build it with `go build` when `go` is on PATH and skip otherwise, keeping a Swift test upstream for the unit tests. It also listens on a Unix socket (`-unix PATH`) to test that path.

## Acceptance criteria

- The real binary from the example config: `curl -k https://…/` serves the static index, `curl -k https://…/api/items` (GET/POST/PUT/DELETE) reaches the Go app over h1, h2 and h3, `/api/echo` shows `X-Forwarded-For/Proto/Host` set correctly, and a WebSocket upgrade through a mount works (Swift test upstream). A config error naming the bad key exits 1.
- Benchmark in `docs/benchmarks/M17-proxy.md`: proxied hello-world keep-alive throughput and the added p50/p99 latency compared with hitting the upstream directly, alongside Apache `mod_proxy` (`/usr/sbin/httpd` with `ProxyPass`, loopback only) and nginx `proxy_pass` on the same upstream.
