# 0008 — Receive errors fall through to request parsing because break only exits the switch

| | |
|---|---|
| **Status** | open |
| **Module** | Connection |
| **Platform** | macOS |
| **First seen** | 2026-09-12 |

## Description

In `HTTPServer.swift:139-146`, the `.error` case sends a 500 and then calls `break`. Inside a `switch`, `break` leaves the `switch`, not the `for await` loop, so execution continues to `HTTPRequest.parse` and may send a second response (400 or 200) on the connection that is being cancelled.

## Expected behavior

A receive error sends at most one response and ends connection handling.

## Actual behavior

The error path falls through to parsing and can send a second response.

## Notes

Use a labeled loop (`receive: for await …` with `break receive`) or `return`. Also consider whether a 500 should be sent at all when the transport itself failed.
