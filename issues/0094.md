## Description

Applications beyond static files need method + path routing without pulling in a framework.

## Scope

- Route table built once at startup: literal segments, `:param` captures (as byte ranges), trailing wildcard; method matching with automatic `405` + `Allow` and `HEAD` from `GET`.
- Matching by a precomputed segment trie with no allocation per request; captured params exposed via `RequestContext`.
- Falls through to the next middleware on no match.

## Acceptance criteria

- Tests for literal, param and wildcard routes, precedence, 405 with Allow, and fall-through.
- `sws-bench router` shows 0 allocations per match for a 50-route table and no change (< 2%) when the component is unregistered.

## Root cause

New component: the `Router` target was a placeholder namespace.

## Fix

- DSL: `try Router { GET("/users/:id") { request, context in … }; POST(…); Group("/api") { … }; Route("/x", methods: [.put, .patch]) { … } }` (result builder with `if`/`else`/`for`). `Route(_:methods:handler:)` and `GET(_:handler:)` also mount an `HTTPHandler`, which finds the params in `context.routeParameters`.
- Compiled once into a flat segment trie (`RouteTable`): node, edge, method-entry and terminal arrays of plain structs indexed by `Int32`; literal edges sorted by (length, bytes) and binary searched. Precedence per segment: literal, `:param` (non-empty segment), trailing `*`/`*name`, with backtracking. Literal pattern bytes outside `pchar` are percent-encoded at build time and compared with the raw request path.
- Captures are byte ranges packed inline in `RouteParameters` (8 slots, one bit each for "contains `%`"); `params["id"]` makes the `String` on demand and percent-decodes only flagged captures. `withBytes`/`decimal`/`view` read without allocating.
- Method handling: a `GET` route answers `HEAD` unless a `HEAD` route exists; a path matched only for other methods answers `405` with `Allow` (prebuilt per pattern, combined when several patterns match); a lower-precedence route that answers the method wins over a `405`. No match falls through to `next` (as a handler: `404`).
- Build errors (`RouterError`): pattern not starting with `/`, `*` not last, empty/invalid/duplicate parameter names, more than 8 captures, empty method list, and conflicts (same shape, overlapping methods; parameter names do not disambiguate).
- `sws-bench router` (alias of `micro --filter Router`) over a 50-route table.

## Gotchas

- `HTTPRequest` has no has-percent flag (only `HTTP1RequestHead` does), so the router records it per capture while scanning segment boundaries; it costs nothing extra.
- Setting a `RequestContext` value allocates one node, so closure routes get params in `RouteContext` (no allocation); only `HTTPHandler` routes pay for `context.routeParameters`.
- The 405 path first collected matching patterns into an array (1 alloc, 110 ns); it now counts them with a non-escaping visitor and only builds a combined `Allow` when more than one pattern matches.
- `Router` must be built before the server's builder block (`let router = try Router { … }`), since the builder closure cannot throw.
- The <2% "unregistered" criterion holds by construction (no change outside Router and sws-bench); `h1conn` was not rerun because other agents were building.
