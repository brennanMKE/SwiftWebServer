## Description

RFC 9113 §7 defines 14 error codes, and every protocol violation must be classified as a connection error (GOAWAY) or a stream error (RST_STREAM). Encode that distinction in the type system so the state machine cannot get it wrong.

## Scope

- `HTTP2ErrorCode` covering NO_ERROR through HTTP_1_1_REQUIRED, with unknown codes preserved.
- `enum HTTP2Error: Error { case connection(HTTP2ErrorCode, reason: String), stream(id, HTTP2ErrorCode, reason: String) }`.
- Debug data for GOAWAY. Reasons are logged but never leak internals to the client.

## Acceptance criteria

- Unit tests for wire values.

## Root cause

The `HTTP2` target had no error model. Feature work: every later HTTP/2 layer (frame codec, SETTINGS, connection and stream state machines) needs a shared way to say which error code to send and whether the violation ends the connection or one stream.

## Fix

- `HTTP2ErrorCode`: an open `RawRepresentable` struct over `UInt32` with static constants for the 14 RFC 9113 §7 codes, `allDefined`, `isDefined`, and an RFC-spelled `name` (`UNKNOWN` for undefined codes). Unknown wire values round-trip unchanged.
- `HTTP2Error`: `enum { case connection(HTTP2ErrorCode, reason: String), stream(HTTP2StreamID, HTTP2ErrorCode, reason: String) }`, with `code`, `streamID`, `isConnectionError`, `reason`, and `onStream(_:_:reason:)`, which escalates a stream error on stream 0 to a connection error.
- GOAWAY debug data is `goawayDebugData`, the code name only. The `reason` is for logs and is never encoded.
- `HTTP2StreamID`: a 31-bit identifier; `init(wireValue:)` masks the reserved bit; parity helpers for client/server-initiated streams.

## Gotchas

- `reason` is a `String`, as the issue specified. It is only built on error paths, and literal reasons do not allocate.
- Frame-level stream errors are not thrown by the frame parser (#0034). A throw loses the consumed-byte count, so the parser reports them as an event and stays usable. Only connection errors are thrown.
