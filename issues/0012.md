# 0012 — Idle connections are never timed out because keepAliveTimeout is ignored

| | |
|---|---|
| **Status** | open |
| **Module** | Security / Connection |
| **Platform** | macOS |
| **First seen** | 2026-09-12 |

## Description

A client that opens a TCP connection and sends nothing (or sends one byte every few seconds) holds a connection and a task forever. `HTTPConfig.keepAliveTimeout` is decoded but never used. This is a slowloris-style resource exhaustion.

## Steps to reproduce

1. `nc localhost 8080` and send nothing.
2. The connection stays open indefinitely.

## Expected behavior

Connections that do not complete a request header section within a timeout, or that stay idle between keep-alive requests for longer than `keepAliveTimeout`, are closed. For HTTP/1.1 a `408 Request Timeout` may be sent first.

## Actual behavior

There is no timeout.

## Notes

Implement with structured concurrency (race the read against `Task.sleep(for:)` in a task group, or use a deadline-aware iterator), not a `DispatchSourceTimer`.
