# 0007 — Receive loop keeps parsing after the response is sent and never resets the buffer

| | |
|---|---|
| **Status** | open |
| **Module** | Connection |
| **Platform** | macOS |
| **First seen** | 2026-09-12 |

## Description

After sending a response, the loop in `HTTPServer.swift:134-170` keeps iterating the connection's data. The buffer still holds the first request, so any further bytes (a request body, a pipelined request, or a late header fragment) cause the same request to be parsed and answered again on a connection that is already being cancelled.

## Steps to reproduce

1. `(printf 'GET / HTTP/1.1\r\n'; sleep 0.5; printf 'Host: x\r\n\r\n') | nc localhost 8080`
2. Watch the debug log for two "Sending response" entries.

## Expected behavior

One response per request. The loop exits (or, after keep-alive is added, resets the buffer) once a response is sent.

## Actual behavior

Duplicate processing of the same buffered request.

## Notes

The `return` on the bad-request path (`HTTPServer.swift:157`) exits the task, but the success path does not.
