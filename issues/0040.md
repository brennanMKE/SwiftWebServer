## Description

Decode complete header blocks into ordered header field lists (RFC 7541 §6).

## Scope

- Indexed field, literal with incremental indexing, literal without indexing, and literal never indexed (the never-indexed flag is surfaced to callers).
- Dynamic table size updates are allowed only at the start of a block and must not exceed the `SETTINGS_HEADER_TABLE_SIZE` the server advertised.
- The maximum header list size is enforced incrementally while decoding, which defeats HPACK bombs.
- Any error is a connection-level `COMPRESSION_ERROR`, and the decoder state is unusable afterward.

## Acceptance criteria

- RFC 7541 Appendix C.3, C.4, C.5, and C.6 request and response sequences decode, including the dynamic table contents after each step.

## Relation

- **Milestone:** M11 — HTTP/2 codecs (Track B)
- **Blocked by:** #0039, #0088, #0095
- **Blocks:** #0041, #0046
- **Note:** prefix integers, string literals and Huffman come from `HeaderCompression` (#0095), which replaces #0037 and #0038.

## Root cause

Feature work: HPACK had tables (#0039) but no decoder.

## Fix

- `HPACKDecoder` is a value type with no I/O. `decode(_:into:)` takes a complete block as a `Span<UInt8>` (with an overload for a `ByteView` of a `ByteBuffer`) and calls a generic `HPACKFieldSink` once per field, with an `HPACKRepresentation` (`indexed`, `incrementalIndexing`, `withoutIndexing`, `neverIndexed`).
- No per-field allocation. Raw literals are passed as spans of the block, indexed fields as spans of the table arena, and Huffman strings are decoded through `StringLiteral.decode` into one reused scratch array. Prefix integers come from `PrefixInteger.decode` with the 2^32 − 1 HPACK bound.
- Size updates are accepted only before the first field and only up to `maxTableSizeLimit`, our acknowledged `SETTINGS_HEADER_TABLE_SIZE`. `setMaxTableSizeLimit` below the current size requires the next block to start with an update.
- The header list size (name + value + 32 per field) is checked before each field is emitted, so a bomb of one-byte references fails at the first field over the limit.
- Every failure is a typed `HPACKError`, all of which mean `COMPRESSION_ERROR` (`http2ErrorCode` 0x9). After any failure `isUnusable` is set and later calls throw `.decoderUnusable`.
- Mapping for #0036: `HTTP2` should turn any `HPACKError` into `HTTP2Error.connection(.compressionError, reason: "\(error)")`.

## Gotchas

- RFC 9113 lets a server answer an oversized header list with 431. Here it is `COMPRESSION_ERROR` because aborting mid-block leaves the table out of sync with the peer. HTTP2 can still send 431 for lists under this hard limit but over a softer one.
- A literal with incremental indexing whose name is a dynamic entry that the insertion evicts goes through `insert(nameOfEntryAt:)`, which moves the name bytes before reusing them. An entry larger than the table is emitted first, then the table is emptied.
