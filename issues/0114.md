## Description

During a full `scripts/guarded.sh -t 1500 -- swift test -j 2` run on merged main (ec71fac, load average about 50 while other agents ran load benchmarks), the `IntegrationTests` test helper (`swiftpm-testing-helper … IntegrationTests`) stopped making progress for 24 minutes at about 58% CPU. A child `sws-bench serve --port 0` was still alive. The guard timed out the run at 1500 s, but the helper and its child were outside the killed process group and had to be killed by hand. The last test the log showed starting was `badConfigFileExitsOneWithAMessage` in the serve child-process tests.

The same suite then passed on its own: 26 tests in 2.3 s.

## Expected behavior

Every async test has `.timeLimit(.minutes(1))`, so a hang should fail within a minute. Child processes should always be killed, and the test run should never outlive the guard.

## Actual behavior

The hang went past the time limit. The helper spinning at 58% CPU suggests a busy wait, perhaps polling the child's stdout or exit status, that never suspends, so the cancellation behind `.timeLimit` is never observed.

## Notes

- Check the child-process helpers in `Tests/IntegrationTests` (#0079 ServeProcessTests): look for busy loops on `Process`/pipe reads, `waitUntilExit()` on the cooperative pool, and readiness polling without `Task.sleep` or a cancellation check.
- Make every child-process wait cancellation-aware, with a hard deadline that SIGKILLs the child.
- `scripts/guarded.sh`: `swift test` starts `swiftpm-testing-helper` in its own process group, so killing the guard's group leaves it behind. On timeout, also kill descendants: walk `pgrep -P` recursively.

## Root cause

Every child-process helper could block or ignore cancellation. `ChildProcess` in `ServeProcessTests` called `Process.waitUntilExit()` on a cooperative-pool thread in both `waitForExit` and `kill()` (the `defer` on every serve test). `waitUntilExit()` spins the current run loop until Foundation notices the exit, and a pool thread has no run-loop sources, so it busy-waits and never observes task cancellation: the 58% CPU and the missed `.timeLimit`. The curl helpers (`HTTP1IntegrationTests.runCurl`, `H3CurlTests.runCurl`, `QUICTransportTests.runProcess`, `TCPTransportTests.runProcess`) blocked pool threads on `readDataToEndOfFile()` plus `waitUntilExit()`, or awaited an uncancellable continuation, and none killed its child when the test was cancelled. Under heavy load a few blocked pool threads are enough to starve the suite.

## Fix

New shared `HTTPTestSupport.ChildProcess` (public). Output arrives through `FileHandle.readabilityHandler` and the exit through `Process.terminationHandler`, both on Foundation threads, into a `Mutex`-guarded state. Waiters suspend on continuations, and each wait races a `Task.sleep(until:)` deadline in a task group under `withTaskCancellationHandler`. On a timeout or a cancellation the child gets SIGKILL and the helper waits (bounded, uncancelled) for the exit to be reaped before throwing. `kill()` is non-blocking (SIGKILL only), and `deinit` kills as a backstop. API: `init(executable:arguments:mergeStandardError:)`, `waitForExit(timeout:)`, `waitForLine(timeout:_:)`, `signal(_:)`, `kill()`, `stdout`/`stderr`/`exitStatus`/`terminationReason`, and `ChildProcess.run(_:_:timeout:mergeStandardError:)` for short-lived tools. The IntegrationTests `sws-bench` launcher and `listeningPort()` are now an extension on it, and all four curl helpers call `ChildProcess.run` with a hard deadline.

## Verification

- Before the fix: IntegrationTests 10 times in a row (`scripts/guarded.sh -t 240 -- swift test -j 2 --skip-build --filter IntegrationTests`) with 12 `yes > /dev/null` running. Run 4 hung with no output until the guard killed it at 240 s (load about 107). The other 9 passed in about 2.2 s. The new guard left no orphans.
- After the fix: the same 10 runs under the same load (load 33 to 46) all passed: 26 tests in about 2.1 s each, 6 to 7 s wall time per run.
- New `HTTPTestSupportTests/ChildProcessTests` (6 tests: output/status capture, merged stderr, timeout kills and reaps, cancellation kills and reaps, `waitForLine` early exit, and `waitForLine` against a live child) ran and passed. Curl tests ran and passed: `servesCurl`, `curlHTTP3OnlyGetsAHandEncodedResponse`, `curlReusesTheConnection`, `curlPostEchoesAFile`, and the 3 `H3CurlTests`.
- Full `scripts/guarded.sh -t 900 -- swift test -j 2`: every test run passed, and `pgrep -fl "$PWD/.build"` was empty afterwards.

## Files changed

- `Tests/HTTPTestSupportTests/ChildProcessTests.swift`: new tests for the helper.

## Gotchas

- Never call `Process.waitUntilExit()` from async code: it spins the run loop and busy-waits on a cooperative thread. Bridge `terminationHandler` instead, and set it before `run()`.
- The pre-fix hang printed nothing at all, not even test-start lines, because `swift test` buffers the helper's output and lost it when the guard killed the run. So the log does not show which test hung. Keep using `guarded.sh`, which now kills descendants.
- `HTTPTestSupport` builds with `InternalImportsByDefault`, so a public API using `URL`/`Process` needs `public import Foundation`.
- Not changed: `TestIdentity.runScript()` still runs `make-test-identity.sh` synchronously (`readDataToEndOfFile` + `waitUntilExit`). It runs at most once per process, only when the identity is missing, and its API is synchronous. A follow-up could bound it.
