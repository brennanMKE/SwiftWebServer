## Description

In the `HTTP2` target (declared by #0069), add a value-type model of all frames from RFC 9113 §6 and a synchronous encoder and decoder that read from and write to `ByteBuffer` (#0073).

## Scope

- 9-octet frame header: 24-bit length, type, flags, reserved bit, and 31-bit stream identifier.
- Frame types DATA, HEADERS, PRIORITY, RST_STREAM, SETTINGS, PUSH_PROMISE, PING, GOAWAY, WINDOW_UPDATE, and CONTINUATION. Unknown types are preserved so they can be ignored (§5.5).
- Flags (END_STREAM, END_HEADERS, PADDED, PRIORITY, ACK) and padding removal with validation.
- Per-type validation: required or forbidden stream id 0, fixed lengths (PING 8, RST_STREAM 4, WINDOW_UPDATE 4, PRIORITY 5, SETTINGS a multiple of 6), and `FRAME_SIZE_ERROR` versus `PROTOCOL_ERROR` as the spec requires.
- Typed throws with `HTTP2Error` (#0036).

## Acceptance criteria

- Round-trip tests for every type.
- Tests for every malformed-length and stream-id rule, each asserting the correct error code.

## Relation

- **Milestone:** M11 — HTTP/2 codecs (Track B)
- **Blocked by:** #0073, #0088, #0095
- **Blocks:** #0035, #0043

## Root cause

The `HTTP2` target had no frame model. Feature work: the connection layer (#0035, #0043, #0044) needs a frame codec that never allocates per frame and reports every RFC 9113 §6 violation with the right code and scope.

## Fix

- `HTTP2FrameTypes.swift`: `HTTP2FrameType` (open set), `HTTP2FrameFlags`, the 9-octet `HTTP2FrameHeader`, `HTTP2Priority`, and `HTTP2Settings`. `HTTP2Settings` keeps the known identifiers (including RFC 8441 ENABLE_CONNECT_PROTOCOL and RFC 9218 NO_RFC7540_PRIORITIES), ignores unknown ones, and keeps the last value of a duplicate. It validates values per §6.5.2.
- `HTTP2FrameParser`: a value-type state machine with the same shape as `H3FrameParser`. `parse(_:)` returns one event plus the bytes consumed, and accepts an `UnsafeRawBufferPointer` or a `ByteBuffer`. A frame header that straddles inputs is accumulated byte by byte. DATA is reported as `dataHeader` (data length, flow-controlled length, END_STREAM), then `data(range)` slices of the caller's input. Padding is validated and skipped. Every other payload is reported in place when it arrives whole. Otherwise it is collected in one reused buffer, bounded by `maxFrameSize` (settable between frames, after the SETTINGS ACK). HEADERS, PUSH_PROMISE and CONTINUATION payloads are opaque fragments with padding and priority fields removed. Unknown types are reported as `.unknown(header)` and skipped.
- Validation:
  - Frame length above SETTINGS_MAX_FRAME_SIZE: FRAME_SIZE_ERROR.
  - Stream 0 required (SETTINGS, PING, GOAWAY) or forbidden (DATA, HEADERS, PRIORITY, RST_STREAM, PUSH_PROMISE, CONTINUATION): PROTOCOL_ERROR.
  - Fixed lengths: PING 8, RST_STREAM 4, WINDOW_UPDATE 4, GOAWAY at least 8, SETTINGS a multiple of 6, SETTINGS ACK empty. Each violation is FRAME_SIZE_ERROR.
  - A payload too short for its Pad Length or priority fields: FRAME_SIZE_ERROR. Padding that exceeds the payload: PROTOCOL_ERROR.
  - PUSH_PROMISE received by a server: PROTOCOL_ERROR (§8.4). SETTINGS_ENABLE_PUSH 1 from a server: PROTOCOL_ERROR.
  - Stream errors are PRIORITY with a length other than 5 (FRAME_SIZE_ERROR), a self-dependent PRIORITY, and a WINDOW_UPDATE of 0 on a stream (both PROTOCOL_ERROR). They come back as a `.streamError(HTTP2Error.stream…)` event after the frame is consumed. A WINDOW_UPDATE of 0 on stream 0 is a connection error.
  - Connection errors are thrown with typed `throws(HTTP2Error)`.
- `HTTP2FrameEncoder`: writes each frame into `ByteBuffer` with one capacity reservation and no staging. Padding is optional on DATA, HEADERS and PUSH_PROMISE. `encodeDataHeader` lets the caller write the body itself. `encodeGoaway(lastStreamID:error:)` sends only the code name as debug data.
- `Sources/sws-bench/H2FrameBench.swift`: parse ns/frame, whole buffer and 37-byte chunks. It is exposed but not registered.

## Gotchas

- A `.buffered` location stays readable until the next buffered frame begins. The buffer is cleared in `begin`, not after completion, so clearing cannot invalidate a location that was just returned.
- The frame layer does not enforce CONTINUATION sequencing or header-block size. Both belong to #0046, which can enforce them using `.unknown` events and `endHeaders`.
- Self-dependency in a HEADERS priority block is not checked here, because a HEADERS block must still be HPACK-decoded. The stream layer should check it.
- In test helpers, `String(reflecting: self)` inside `description` recurses and crashes the test process with SIGBUS when an expectation fails.
- Passing `throws(E)` closures to `Array.withUnsafeBytes` in tests crashed the 6.4.2 compiler (an OperandOwnership assertion). The tests parse through `ByteBuffer` instead.
