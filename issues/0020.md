# 0020 — Responses omit the Date and Connection headers

| | |
|---|---|
| **Status** | open |
| **Module** | Semantics |
| **Platform** | macOS |
| **First seen** | 2026-09-12 |

## Description

Responses have no `Date` header, which RFC 9110 §6.6.1 requires from an origin server with a clock. The server closes every connection after one response but does not send `Connection: close`, so HTTP/1.1 clients assume keep-alive and try to reuse a socket that is about to close. `docs/PROJECT.md` claims `Connection: close` is sent.

## Steps to reproduce

1. `curl -sI http://localhost:8080/index.html`

## Expected behavior

`Date: <IMF-fixdate>` and, while connections are not reused, `Connection: close`.

## Actual behavior

Neither header is present.

## Notes

Once #0033 adds keep-alive, `Connection: close` should only be sent when the server actually intends to close.
