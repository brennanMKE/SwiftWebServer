# 0035 — Decode frames from a byte AsyncSequence as an AsyncSequence of frames

|---|---|
| **Status** | open |

## Description

Provide a `FrameParser` value-type state machine fed from the connection's reusable `ByteBuffer`, and a demand-driven frame `AsyncSequence` whose `next()` calls `ByteStreamTransport.receive(into:)` only when the parser needs more bytes (ROADMAP §5.4). This replaces the earlier `AsyncSequence<ArraySlice<UInt8>>.http2Frames()` design; there is no per-read `Array` copy.

## Scope

- The iterator accumulates bytes until a full frame is available and yields exactly one frame per `next()`, handling frames split across reads and several frames in one read.
- Frames longer than the current `SETTINGS_MAX_FRAME_SIZE` produce `FRAME_SIZE_ERROR`. The limit can change after SETTINGS is acknowledged.
- Clean end of input between frames finishes the sequence. End of input mid-frame throws.
- Buffering never holds more than one maximum frame plus one read.

## Acceptance criteria

- Tests feed the same frames with 1-byte reads, whole-buffer reads, and random splits, and assert identical output.
