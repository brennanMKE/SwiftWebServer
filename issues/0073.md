## Description

Every protocol layer parses and writes bytes directly (ROADMAP §7). Provide the one reusable byte container and the small ASCII helpers they all share, so no layer reaches for `Data`, `String` or Foundation on the hot path.

## Scope

- `ByteBuffer`: one growable buffer with separate reader and writer indices, `reserveCapacity`, `discardReadBytes` (compaction), `clear(keepingCapacity:)`, read/write of integers in network byte order, and borrowing views (`ByteView`) over ranges without copying. Unsafe pointers are confined to this type (ROADMAP §7 "Keep unsafe small"); use `Span`/`RawSpan` if #0069 found them available.
- `ByteView` / byte-range type used by `HTTPRequest` for path, query, authority and header values; `String` only on demand via an explicit conversion.
- ASCII utilities: 256-entry token and field-value tables, case-insensitive compare of lowercase literal against bytes, CR/LF scanning, decimal digit loops for `Content-Length` with overflow detection, hex parsing for chunk sizes, integer-to-ASCII into a buffer without `String`.
- FNV-1a hash of lowercased bytes computed in the same pass as a scan (used by #0074 for header name IDs).
- `BoundedAsyncQueue` and `Deadline` utilities from ROADMAP §5.4 if not owned elsewhere: a queue that suspends producers when full, with cancellation-safe waiters.

## Acceptance criteria

- `swift test --filter HTTPCoreTests` runs index, compaction, growth and integer round-trip tests, including overflow and reading past the writer index.
- `sws-bench bytes` reports 0 allocations per op for read/write/compaction after warm-up, and integer-to-ASCII under 20 ns.
- `BoundedAsyncQueue` tests show a producer suspends at capacity and resumes when a consumer reads, and that cancelling a suspended producer removes its waiter.

## Root cause

New work (M1.1): no shared byte container or ASCII helpers existed in `HTTPCore`; every layer would otherwise reach for `Data`/`String`.

## Fix

- `ByteBuffer`: copy-on-write `Sendable` struct over a `final class` storage (`isKnownUniquelyReferenced` guards every mutation). It is copy-on-write rather than noncopyable because the §5.2 APIs need `Copyable` buffers: `send(_ bytes: ByteBuffer)` and `HTTPRequestBody` as an `AsyncSequence` of `ByteBuffer`. Growth at least doubles (minimum 64) and copies `0..<writerIndex` to the same indices, so `ByteView`s stay valid across growth and copies; only `discardReadBytes()` (when it returns `true`) and `clear` invalidate them. `discardReadBytes` resets the indices for free when everything has been read, and otherwise compacts only when readable ≤ consumed, so the copy never exceeds the space it frees. Tail receive: `withUnsafeMutableWritableBytes(minimumWritableBytes:)` + `commitWritten(_:)`. Writes: bytes, `StaticString`, `Span`, `RawSpan`, sequences, other buffers or views, `append(decimal:)` and `append(hex:)` without `String`, and `append(bigEndian:)` / `getInteger(at:)` / `readInteger()` (network byte order; `nil` when past the writer index). Reads: `withUnsafeReadableBytes`, `withReadableSpan`, `withReadableRawSpan`, `withSpan(of: ByteView)`. `Data` conversion lives in `ByteBuffer+Data.swift` for transport edges. All pointer code is in `ByteBuffer.swift`, behind preconditions on the index invariant.
- `ByteView`: `(offset, length)` with absolute indices; `string(in:)`, `equalsCaseInsensitive(_:in:)`, `equals`, `decimalValue`, `hexValue`, `fnv1aLowercased`, `subview`.
- `ASCII`: 256-entry `tchar` and field-value tables stored as 4×`UInt64` bit tables (constant-folded, so there is no lazy global or array bounds check), lowercase folding, `firstIndex(of:)` / `firstCRLF`, an incremental `FNV1a` hasher plus one-pass `fnv1aLowercased`, `parseDecimal` and `parseHex` over `Span<UInt8>` with overflow checks, and digit counts.
- `BoundedAsyncQueue<Element>`: `Mutex` state, a preallocated ring, many producers and one consumer. Producers suspend at capacity. Cancellation is checked under the lock before a waiter registers, so it never races the handler. Cancelling a producer removes its waiter and drops the element. `finish()` drains, then ends. Continuations are resumed outside the lock.
- `Deadline`: a `ContinuousClock` instant or `.never`, with `hasExpired`, `remaining` and `earliest`.
- `Sources/sws-bench/ByteBufferBench.swift`: `runByteBufferBenchmarks()` returns `(name, ns/op)`, not wired into `main` (the #0070 harness owns `main`).

## Verification

- `scripts/guarded.sh -t 600 -- swift test`: all targets pass. `HTTPCoreTests` ran 80 tests in 7 suites, including the new `ByteBufferTests`, `ByteViewTests`, `ASCIITests`, `BoundedAsyncQueueTests` and `DeadlineTests`. They cover empty buffers, growth across capacity, geometric growth, discard/compact (no-op, reset, compact, skip, shared storage), clear, copy-on-write, view stability, tail commit, `Data` round-trip, big-endian round-trip and reads past the writer index, decimal and hex overflow and edge cases, all 256 bytes of both tables, FNV-1a reference vectors, CRLF splits, and exit tests showing that index misuse traps.
- `BoundedAsyncQueueTests`: a producer suspends at capacity (`suspendedProducerCount == 1`) and resumes after `next()`, and cancelling a suspended producer leaves `suspendedProducerCount == 0` with the element dropped. These tests passed 15/15 repeated runs.
- `swift build -c release --product sws-bench` builds. Benchmarks used `swiftc -O -wmo` with the same sources and a scratch driver, because `main` stays unwired. Results on an arm64 Mac: append decimal 10.0 ns/op (target < 20 ns), append+parse decimal 33 ns, append+parse hex 32–54 ns (16-digit values), static append + discard 6–7 ns, FNV-1a of `Content-Type` 4.4 ns.

## Gotchas

- Allocation-per-op reporting (`sws-bench bytes … 0 allocations`) depends on the #0070 harness, which owns `main` and the allocation counter. Wire `runByteBufferBenchmarks()` into a `bytes` suite there. The steady state reuses one buffer and should allocate nothing.
- Swift Testing's `#expect` cannot take a `Span` (`~Escapable`) property access or a mutating call. Bind the value to a local first.
- `ByteView`s index the buffer absolutely, so a view taken before `discardReadBytes()` returns `true` reads the wrong bytes (there is no generation check yet; ROADMAP §5.2 mentions a debug generation counter for `HTTPRequest`). Call `discardReadBytes` only between requests.
- `BoundedAsyncQueue` allows one consumer at a time, enforced by a precondition.
- Hex parse is the slowest path (about 2–3 ns/digit). A SWAR or table lookup can come later if chunked decoding shows up in profiles.
