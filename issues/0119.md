## Description

The `SwiftWebServer` executable registers only `HTTP1`, and `ConfigFile` has no `http2` key, so the shipped server never speaks HTTP/2: `curl --http2 -k https://` negotiates HTTP/1.1, and `curl --http2-prior-knowledge http://` fails. HTTP/2 exists only in `sws-bench serve --h2` (#0042 Gotchas).

## Steps to reproduce

1. `swift run SwiftWebServer --config Root/http-config.tls.json`
2. `curl -sk --http2 -o /dev/null -w '%{http_version}\n' https://127.0.0.1:8443/`

## Expected behavior

- A config key `http2: {enabled, cleartext, maxConcurrentStreams, initialWindowSize, maxRequestBodySize, abuseLimits}`, documented in the README's config table.
- HTTP/2 is on by default for TLS: the TLS listener offers `h2` and `http/1.1` via ALPN (#0088 registry list).
- Cleartext prior-knowledge h2c only with `"cleartext": true`. The default cleartext path stays HTTP/1.1-only with no sniff or replay wrapper (#0042 Gotchas).
- The sniff and replay cost of enabling h2c is measured (`docs/benchmarks/M13-h2.md`); a cost over 5% becomes a follow-up issue.
- Tests launch the real binary from a config: `curl --http2 -k https://` gives HTTP/2 200, `--http1.1` still works, `--http2-prior-knowledge http://` only with cleartext enabled, `Alt-Svc` still present on HTTPS, and config validation errors exit 1.

## Actual behavior

HTTP/1.1 only, on every listener.

## Relation

- **Milestone:** M13
- **Blocked by:** none
- **Blocks:** M13 exit checks against the shipped server (`curl --http2`, h2spec, h2load)

## Root cause

`ServerMain` registered `[HTTP1]` only and `ConfigFile` had no HTTP/2 settings, so the TLS listener's ALPN list from the registry (#0088) held only `http/1.1`. Registering `[HTTP2, HTTP1]` as `sws-bench serve --h2` does would have sent every cleartext connection through the sniff and `PrefixedTransport` (#0042 Gotchas), even when nobody wants h2c.

## Fix

- **ConfigFile:** `ServerSettings.http2: HTTP2Settings?`, on by default (`cleartext` false, `maxConcurrentStreams` 100 in `0...65536`, `initialWindowSize` 65,535 in `0...2^31-1`, `maxRequestBodySize` defaulting to `maxBodySize`, `abuseLimits` overrides where JSON `null` turns a limit off). These are plain values, so ConfigFile does not link HTTP2. `"http2": false` / `null` / `"enabled": false` turns it off. Bad values throw naming the key, and unknown subkeys warn.
- **Executable:** `ServerProtocols.make` builds the registry list. HTTP/2 off gives `[HTTP1]`. HTTP/2 on with cleartext off gives one protocol, `TLSNegotiatedHTTP2`: its ALPN tokens are `h2, http/1.1`, and it runs HTTP/2 only on a TLS connection that negotiated `h2`, otherwise HTTP/1.1. With a single protocol the registry never sniffs, so the default cleartext path matches HTTP/1.1 alone. Cleartext on gives `[HTTP2, HTTP1]` with sniffing. The `HTTP2Configuration` maps the settings, and its `idleTimeout` is `timeouts.idle`, so an idle h2 connection does not hold a connection slot forever. HTTP2 is linked through the `HTTP2` package trait (one line in `Package.swift`). If the trait is off, `cleartext: true` is a config error and TLS stays HTTP/1.1.
- `Root/http-config.json` and `Root/http-config.tls.json` spell out the `http2` defaults. The README config table documents the key.

## Gotchas

- Issue numbers collided: 0116 and 0117 landed on main and another worktree holds 0118 while this was filed, so this issue was renumbered from 0116 to 0119 before merging.
- Turning HTTP/2 on by default for TLS changes what clients negotiate: system curl and Homebrew curl use h2 over HTTPS when it is offered. Tests that expected `1.1` on HTTPS had to be updated.
- With `cleartext: true` the cleartext port is shared with HTTP/1.1. h2spec 3.5/2 (a client that sends no valid preface gets an HTTP/1.1 400) fails there by design (#0061). The h2spec runs use `sws-bench serve --h2-only`.
- A single protocol wrapper (`TLSNegotiatedHTTP2`) avoids the sniff without changing `HTTPServer`. If the registry ever gets per-listener protocol lists, this wrapper can go.
- oha `--http2` sends one stream at a time per connection, so its h2 numbers measure per-exchange latency, not multiplexing.
