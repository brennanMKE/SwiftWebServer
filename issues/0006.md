# 0006 — Request parser accepts incomplete data as a complete request

| | |
|---|---|
| **Status** | open |
| **Module** | HTTP1 |
| **Platform** | macOS |
| **First seen** | 2026-09-12 |

## Description

`HTTPRequest.parse(from:)` (`HTTPRequest.swift:36-74`) returns a request as soon as the first line contains two space-separated tokens. It never checks for the `\r\n\r\n` that ends the header section. A request split across TCP reads is answered using only its first fragment, and headers that arrive later (such as `If-None-Match`) are silently ignored. A fragment that ends mid request line (for example, `GE`) is rejected with 400.

## Steps to reproduce

1. Start the server.
2. `(printf 'GET /index.html HTTP/1.1\r\n'; sleep 1; printf 'Host: localhost\r\nIf-None-Match: <etag>\r\n\r\n') | nc localhost 8080`

## Expected behavior

The server waits for the complete header section, then returns 304 for a matching ETag.

## Actual behavior

The server returns 200 immediately after the first line, before the headers are sent.

## Notes

- `HTTPServer.swift:150` calls the parser after every chunk. The parser needs a "need more data" result that is distinct from "malformed".
- The request line is not validated: the HTTP version is optional and never checked, and the method is not checked against token syntax.
- Header bytes should be decoded as ASCII/ISO-8859-1, not required to be UTF-8.
- #0033 replaces this parser with an AsyncSequence codec. Tests written here should carry over.
