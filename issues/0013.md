# 0013 — Block list never matches because entries lack a leading slash and matching is exact

| | |
|---|---|
| **Status** | open |
| **Module** | Security / StaticFiles |
| **Platform** | macOS |
| **First seen** | 2026-09-12 |

## Description

`respond(to:)` checks `blockList.contains(request.path)` (`HTTPServer.swift:188`). Request paths always begin with `/`, but the entries in `Root/http-config.json` are `"http-config.json"`, `".git"`, and `".DS_Store"`, so nothing ever matches. Matching is also exact, so `/sub folder/.DS_Store` or `/.git/config` would be served even if the entries had slashes.

## Steps to reproduce

1. `touch "Root/Public/.DS_Store"`
2. `curl -i http://localhost:8080/.DS_Store`

## Expected behavior

403 Forbidden.

## Actual behavior

200 with the file contents.

## Notes

Match on decoded path components (any component equal to a blocked name), plus optional exact-path entries. The check runs before percent decoding (see #0015), so `/%2EDS_Store` bypasses exact matching as well.
