## Description

The `AccessLog` target (access lines, metrics, `MetricsEndpoint`) exists as a library component, but `ConfigFile` doesn't expose it, so the shipped `SwiftWebServer` binary can't write an access log. That's needed to replace Apache as the public front end.

## Scope

- An `accessLog` config key: output path (a file, `stdout` or `stderr`), the line format (common/combined/json, whatever `LineFormatter` supports), and an optional `metrics` endpoint path.
- `makeHandler` places AccessLog outermost, so it sees the final status of every response, including proxied ones and Auth rejections.
- Per-virtual-host `hosts[].accessLog` if it's simple to add.
- Unknown keys are errors; a bad value gives a config error naming the key (exit 1).
- README: document the key.

## Acceptance criteria

- ConfigFile tests for parsing and errors.
- An integration test with the real binary: requests to static files and to a proxied path each produce one log line in a file under `$TMPDIR`.
