# 0028 — Replace the eager ConnectionStream with a demand-driven AsyncSequence over NWConnection

| | |
|---|---|
| **Status** | open |
| **Module** | Transport |
| **Platform** | macOS |
| **First seen** | 2026-09-12 |

## Description

`ConnectionStream` (`HTTPServer.swift:312-352`) starts a task that calls `receive` in a loop and yields into an unbounded `AsyncStream`, so a fast client can fill memory regardless of how fast the server consumes data. Replace it with a `NWConnectionTransport` whose inbound iterator calls `receive(minimumIncompleteLength:maximumLength:)` only from `next()`.

## Scope

- A custom `AsyncIteratorProtocol` bridges one `receive` callback to one `next()` via `withCheckedThrowingContinuation`, with a cancellation handler that cancels the connection.
- `write` wraps `send(content:completion:)` and suspends until `.contentProcessed`.
- The state handler is installed before `start(queue:)` (#0010). Readiness is awaited before the first read, and failures surface as thrown errors.
- The `@unchecked Sendable` needed for `NWConnection` is confined to this adapter and documented.

## Acceptance criteria

- The existing HTTP/1.1 behavior works through the adapter.
- A test shows that no read happens until the iterator is advanced.
