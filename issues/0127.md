# 0127 — SIGHUP kills the server without draining and there is no config reload

| | |
|---|---|
| **Status** | open |
| **Module** | SwiftWebServer (executable) / ConfigFile |
| **Platform** | macOS |
| **First seen** | 2026-11-12 |

## Description

Found while writing the developer guides. The executable handles SIGINT/SIGTERM with a graceful drain, but SIGHUP isn't handled, so the default action terminates the process mid-request. Front ends like Apache and nginx reload their config (and reopen log files) on SIGHUP, and the access log (#0125) has no rotation, so a reopen hook matters for long-running deployments (for example the LaunchAgents in `Examples/parallax-gordon`).

## Scope

- Handle SIGHUP: at least reopen the access log file (for newsyslog/logrotate-style rotation).
- Optionally reload `http-config.json`: parse and validate the new file; on success swap the handler chain for new requests while in-flight ones finish on the old one; on failure log the error and keep running. Listener address/port/TLS changes may require a restart; document which keys reload.
- No `DispatchQueue` outside the existing signal-source exception.

## Acceptance criteria

- Integration test with the real binary: rename the access log, send SIGHUP, the next request lands in a new file; a config change (for example a new proxy mount) takes effect without dropping an in-flight request; an invalid config on reload keeps the old one.
