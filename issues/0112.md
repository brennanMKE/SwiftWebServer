# 0112 — HTTP/1.1 head parse takes 354 ns for a 10-header request, missing the 150 ns target

## Description

`parse.head` for a typical 10-header browser request takes 354 ns median with 0 allocations (release build, load average about 4.4). ROADMAP §7 targets under 150 ns. The parser agent profiled by removing one step at a time (`docs/benchmarks/M1.3-parser.md`):

- about 130 ns in the 10 `HTTPFieldName.lookup(hash:name:)` calls
- about 40 ns in `HTTPFieldIndex.append`
- about 110 ns floor for FNV-1a over the 116 name bytes: each byte's multiply depends on the previous one

## Scope

- Make well-known name lookup cheaper. Options: compare length plus the first 8 bytes as one integer before a full compare; build a perfect-hash table on (length, a few bytes) so most names need no full hash; or resolve names after the field section so the hash work for different fields can overlap.
- Replace FNV-1a's byte-serial dependency chain. Options: process 8 bytes per step (word-at-a-time multiply-xor), or hash only the length and selected bytes needed by the perfect-hash table. Lowercasing must stay fused into the scan.
- Make `HTTPFieldIndex.append` cheaper: unchecked appends into pre-reserved capacity, and fewer bounds checks in the hot path.
- Keep the differential test against the reference parser and the split-at-every-offset tests green.

## Acceptance criteria

- `parse.head` for the 10-header request is under 150 ns median on an idle machine, with 0 allocations.
- No regression above 10% in any other `micro` benchmark.
- Full `swift test` passes, including the differential and split tests.
