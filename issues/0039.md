## Description

Implement the indexing tables from RFC 7541 §2.3 and §4.

## Scope

- The 61-entry static table (Appendix A) with fast name and name-value lookup for the encoder.
- A dynamic table as a ring buffer, entry size = name + value + 32, FIFO eviction, and a table that can shrink to 0 (§4.4).
- A unified index address space (static 1–61, dynamic 62 and up). Out-of-range indexes throw.

## Acceptance criteria

- Tests for eviction order, a size update that evicts everything, an entry larger than the table (which empties it), and index lookup.

## Relation

- **Milestone:** M11 — HTTP/2 codecs (Track B)
- **Blocked by:** #0088, #0095
- **Blocks:** #0040
- **Note:** prefix integers, string literals and Huffman come from `HeaderCompression` (#0095), which replaces #0037 and #0038.

## Root cause

Feature work: `HPACK` was a placeholder target with no tables.

## Fix

- `HPACKStaticTable`: the 61 Appendix A entries packed into one `ByteArena` on first use, with a precomputed 128-slot open-addressed FNV-1a index from name to its first index. Entries that share a name are contiguous, so `search(name:value:)` scans only that run. Per-name flags mark sensitive names (authorization, cookie, proxy-authorization, set-cookie) and volatile ones (`:path`, content-length, etag, …) for the encoder. Lookups do not allocate.
- `HPACKDynamicTable`: a ring of fixed entry records over a single byte arena, both sized once from `capacity` (the `SETTINGS_HEADER_TABLE_SIZE` bound), so nothing resizes after creation. Size accounting uses the 32-byte overhead, eviction is FIFO, `setMaxSize` evicts down to the new size (0 empties it), and an entry larger than `maxSize` empties the table. `insert(nameOfEntryAt:value:)` handles the RFC 7541 §4.4 case where the referenced name is evicted by the insertion.
- Unified address space: `withField(atIndex:)` and `search(name:value:)` cover 1–61 static and 62+ dynamic; 0 or past the end throws `HPACKError.invalidIndex`.
- `HPACKError` (`http2ErrorCode` = `COMPRESSION_ERROR`, 0x9) since #0036 is not on `main`.

## Gotchas

- To keep entries contiguous, the byte arena is 2 × capacity and an entry that would cross the end goes to offset 0. Live bytes are at most `maxSize − 32·count` and the gap at the end is smaller than one entry, so the doubled arena always has room.
- `Array.span` needs macOS 26, so scratch arrays get spans through `UnsafeBridge` in `ByteArena.swift`.
- Swift Testing's `#expect` cannot wrap a mutating call such as `#expect(table.insert(…))`; bind the result first.
