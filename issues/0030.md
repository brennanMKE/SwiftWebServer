# 0030 — Introduce protocol-agnostic HTTP message types with ordered header fields and streaming bodies

## Description

HTTP/2 needs pseudo-headers, trailers, duplicate fields, and streaming bodies, none of which `HTTPRequest` or `HTTPResponse` can represent. Define shared types that both codecs produce and consume.

## Scope

- `HTTPFields`: ordered, case-insensitive lookup, keeps duplicates, and preserves names for HTTP/1.1 output while lowercasing for HTTP/2.
- `HTTPMethod`, and `HTTPStatus` extended to arbitrary codes with reason phrases.
- `HTTPRequest` with method, scheme, authority, path, query, fields, and `body: HTTPBody`.
- `HTTPResponse` with status, fields, `body: HTTPBody`, and optional trailers.
- `HTTPBody` is an `AsyncSequence<ArraySlice<UInt8>, any Error>` with a known-length hint and convenience initializers (empty, bytes, file).

## Acceptance criteria

- Unit tests cover field lookup, duplicates, and ordering.
- The existing static file responses are expressed with the new types.
- Resolves the dictionary problems in #0021.
