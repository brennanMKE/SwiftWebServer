# 0080 — HTTP/1.1 connection state machine and runner support keep-alive, pipelining and error responses

## Description

The legacy receive loop keeps parsing after the response, never resets its buffer (#0007), falls through to parsing on receive errors (#0008), leaves the connection hanging when a response throws (#0009), and closes after one response. Implement the HTTP/1.1 connection as a pure state machine plus a thin async runner that is the hot loop in ROADMAP §5.3.

## Scope

- `HTTP1Connection` state machine: idle, readingHead, handling, readingBody, writing, closing, tunnelled; persistence per RFC 9112 §9.3 (`Connection: close`, HTTP/1.0 without keep-alive), `Connection` response header decided here (#0020 part).
- `HTTP1` conforms to `ConnectionProtocol`; its runner owns one receive buffer, the parser and the state machine as locals (no actor); one `await` per read and one per pipelined batch write.
- Pipelining: parse every complete head already buffered, respond in order, flush once per batch.
- Receive errors and EOF end the loop cleanly (#0008); a handler throw before the response starts becomes `500` + `Connection: close` (#0009); after headers are sent, the connection closes.
- `.tunnel` responses emit `101 Switching Protocols` and hand the transport to the closure (hook for #0108).
- Buffer compaction after each request so the buffer never grows across requests (#0007).

## Acceptance criteria

- In-memory tests: 100 keep-alive requests on one connection; 10 pipelined requests in one write answered in order with one flush; handler throw → 500 and close; receive error → loop exits, no response attempted; HTTP/1.0 without keep-alive closes.
- `curl -v http://localhost:<port>/a http://localhost:<port>/b` shows `Re-using existing connection`.
- `sws-bench` keep-alive load run with `oha -c 16` beats the legacy baseline from #0070 and allocations per request in our code are 0.
