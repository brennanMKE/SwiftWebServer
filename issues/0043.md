# 0043 — Exchange and apply SETTINGS, including ACK and settings timeout

| | |
|---|---|
| **Status** | open |
| **Module** | HTTP2 |
| **Platform** | macOS |
| **First seen** | 2026-09-12 |

## Description

Implement the SETTINGS handshake (RFC 9113 §6.5).

## Scope

- The server sends its SETTINGS as the first frame, from config.
- Peer SETTINGS are validated: ENABLE_PUSH must be 0 or 1, INITIAL_WINDOW_SIZE at most 2³¹−1 (otherwise FLOW_CONTROL_ERROR), MAX_FRAME_SIZE between 16,384 and 16,777,215, and unknown identifiers are ignored. Valid settings are applied and ACKed.
- Local settings take effect only after the peer's ACK. A missing ACK within the timeout triggers `GOAWAY(SETTINGS_TIMEOUT)`.
- A SETTINGS ACK with a non-empty payload is a `FRAME_SIZE_ERROR`.
- Changes to the peer's INITIAL_WINDOW_SIZE and HEADER_TABLE_SIZE notify flow control (#0054) and the HPACK encoder (#0041).

## Acceptance criteria

- State machine tests cover every validation rule and the ACK-before-apply ordering.
