## Description

Defend against the published HTTP/2 attack classes with counters in the connection state machine. Violations trigger `GOAWAY(ENHANCE_YOUR_CALM)`.

## Scope

- **Rapid reset (CVE-2023-44487):** limit client-initiated resets per time window.
- **CONTINUATION flood (VU#421644):** cap accumulated header block bytes and CONTINUATION count per block.
- **Control-frame floods:** cap queued outbound PING ACKs and SETTINGS ACKs (the writer's control queue depth).
- **Empty frame flood:** limit zero-length DATA frames without END_STREAM, and empty CONTINUATIONs.
- **HPACK bomb:** incremental header list limit (#0040) and a dynamic table bounded by the advertised size.
- **Zero-window stall:** close streams or connections whose send window stays at 0 beyond a timeout.
- **Slow preface:** close if the preface and SETTINGS do not arrive within a timeout.
- Every threshold is configurable, and the defaults come from the limits table and DoS list in `docs/HTTP2.md`.

## Acceptance criteria

- One in-memory transport test per attack asserts GOAWAY and bounded memory.

## Root cause

Feature work. Some defences already existed: CONTINUATION count and block size caps (#0046), the incremental HPACK list limit (#0040), the queued reply control-frame cap (#0044), and the settings timeout (#0043). What was missing:

- rate limits on frames that cost work without carrying a request (rapid reset was left open by #0051);
- any bound on handler tasks of reset streams;
- a defence against small-window and zero-window slow reads;
- a bound on a connection's lifetime stream count.

## Fix

- **`HTTP2AbuseLimits`** (`HTTP2Configuration.abuseLimits`), modelled on HTTP/3's `H3AbuseLimits` (#0104), with `HTTP2AbuseMonitor` counting per connection in a fixed window (`window`, 10 s). `nil` turns a limit off. Each rate below closes with `GOAWAY(ENHANCE_YOUR_CALM)` when exceeded:

  | Setting | Default | Counts |
  |---|---|---|
  | `maxResetStreamsPerWindow` | 100 | RST_STREAM on a stream whose handler still runs, plus streams refused over MAX_CONCURRENT_STREAMS (CVE-2023-44487) |
  | `maxControlFramesPerWindow` | 1,000 | PING, SETTINGS, PRIORITY and unknown-type frames |
  | `maxEmptyFramesPerWindow` | 100 | DATA with no payload and no END_STREAM; HEADERS and CONTINUATION with an empty fragment and no END_HEADERS |
  | `maxWindowUpdatesPerWindow` | 10,000 | WINDOW_UPDATE frames |
  | `maxSmallDataFramesPerWindow` | 1,000 | DATA frames a send window cut below `smallDataFrameSize` (256 B): small-window slow read |

- **Zero-window stall.** `windowStallTimeout` (30 s). Waiters record when they parked, and a watchdog checks every quarter of the timeout. A writer stalled on its stream window gets `RST_STREAM(ENHANCE_YOUR_CALM)`; one stalled on the connection window closes the connection with `GOAWAY(ENHANCE_YOUR_CALM)`.
- **Stream-identifier exhaustion.** `maxStreamsPerConnection` (100,000). The stream that reaches it is served, and the graceful shutdown starts: GOAWAY(2³¹−1), PING, then the final GOAWAY. The client moves to a new connection.
- **Handler tasks of reset streams** count against 2 × MAX_CONCURRENT_STREAMS. Past it, new streams get `RST_STREAM(REFUSED_STREAM)`, which also counts as a reset.
- **Existing defences, verified by tests:** CONTINUATION flood (VU#421644: `maxContinuationFrames`, `headerBlockLimit`), HPACK bomb (`headerBlockLimit`, `COMPRESSION_ERROR`), queued reply flood (`maxQueuedControlFrames`), slow preface (`settingsTimeout`: no preface means no SETTINGS ACK, so `GOAWAY(SETTINGS_TIMEOUT)`).
- **Shutdown PING ordering** (bug found while testing): the graceful-shutdown PING went into the priority lane and could overtake the first GOAWAY when both were in one batch. Its ACK then did not prove the client had seen the GOAWAY (`H2GoawayTests` failed about 1 run in 6). After the shutdown starts, our PING now goes into the ordered lane.
- **Benchmark.** `sws-bench serve --h2` registers HTTP/2 before HTTP/1.1. `docs/benchmarks/M13-h2.md` records the h2load runs. `docs/HTTP2.md` gains an "HTTP/2 abuse limits" table.

## Gotchas

- The client's own first SETTINGS counts as a control frame, so a limit of N allows N − 1 PINGs after the handshake.
- `smallDataFrameSize` is 256 rather than 1 KiB on purpose. Clients that return credit at half a window (nghttp2, browsers) never produce smaller window-limited frames with windows of 512 bytes or more. An h2load run with `-w 10` (1 KiB windows) and a 1 KiB threshold would trip the limit.
- A legitimate client that resets a lot (for example, a browser cancelling navigations) can hit 100 resets in 10 s. The limit is configurable, and `nil` turns it off.
- The handler-task cap is 2 × MAX_CONCURRENT_STREAMS, not 1×. A stream's handler task ends a little after its END_STREAM reaches the client, and a client that opens the next stream at once would otherwise be refused.
- Over a graceful shutdown that the stream limit started, a stream above the final GOAWAY is refused only while other streams still run. Once the last stream ends, the connection closes.
