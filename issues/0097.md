## Description

ROADMAP §6 starts HTTP/3 with QPACK using the 99-entry static table and literals only, advertising `SETTINGS_QPACK_MAX_TABLE_CAPACITY = 0`, so request streams share no mutable compression state.

## Scope

- Static table (RFC 9204 Appendix A) with name and name-value lookup via the well-known header IDs from #0074.
- Decoder: encoded field section prefix (Required Insert Count must be 0, otherwise `QPACK_DECOMPRESSION_FAILED`), indexed static, literal with static name reference, literal with literal name, never-indexed (N) bit surfaced; header list size enforced incrementally.
- Encoder: static indexed or static-name literal when possible, Huffman when shorter, never-indexed for `authorization`, `cookie`, `set-cookie`.
- Encoder/decoder stream instructions parsed and validated (peer may send them even when our capacity is 0; inserts beyond capacity are `QPACK_ENCODER_STREAM_ERROR`).

## Acceptance criteria

- RFC 9204 Appendix B.1 (literal field line with name reference) example encodes and decodes byte-for-byte; static-only field sections round-trip for a corpus of real browser request headers.
- A field section with non-zero Required Insert Count fails with `QPACK_DECOMPRESSION_FAILED`.
- `sws-bench qpack` records ns per 10-field decode and 0 allocations into reused `HTTPFields` storage.

## Root cause

Feature work: the `QPACK` target was an empty placeholder. HTTP/3 (#0101, #0106) needs a static-table-only QPACK codec that matches our advertised `SETTINGS_QPACK_MAX_TABLE_CAPACITY = 0`.

## Fix

- `QPACKStaticTable`: the 99 Appendix A entries (checked against the RFC text) in one flat byte array with offsets. Two 256-slot open-addressed FNV-1a tables, one keyed on name and one on (name, value), are built once as a global `let`. Lookup is byte-exact and allocation-free, returning `.field(i)`, `.name(lowest i)` or `.none`. The well-known header IDs from #0074 are not in `HTTPCore` yet, so lookup hashes the name bytes directly.
- `QPACKEncoder`: writes the `00 00` prefix (Required Insert Count 0, Base 0). For each field it emits, in order of preference, an Indexed Field Line (static), a Literal with Static Name Reference, or a Literal with Literal Name. Strings use `StringLiteral.encode` with the `HuffmanPolicy` (`.whenShorter` by default). `authorization`/`cookie`/`set-cookie` (static indices 84/5/14) always get a literal with the N bit set. Callers can force N for any field.
- `QPACKDecoder`: decodes a complete field section into a `QPACKFieldSink` as borrowed `UnsafeRawBufferPointer`s. Raw strings point into the input and static entries into the table. Huffman strings go through scratch storage that the decoder reuses between sections, so a warm decoder does not allocate. It rejects a non-zero Required Insert Count, Sign = 1 (negative Base), dynamic and post-Base references, static index ≥ 99, truncation, integer overflow and bad Huffman, all with `QPACK_DECOMPRESSION_FAILED` (0x0200) plus a `Reason`. It checks the field section size (name + value + 32) before delivering each field, and also checks a string's declared length against the remaining budget before reading it.
- Stream instructions: `QPACKEncoderInstruction.parse` and `QPACKDecoderInstruction.parse` do incremental structural parsing (string payloads come back as byte ranges). `QPACKEncoderStreamReader` accepts only Set Dynamic Table Capacity 0. A larger capacity, Insert or Duplicate is `QPACK_ENCODER_STREAM_ERROR` from the first byte. `QPACKDecoderStreamReader` accepts Stream Cancellation. Section Acknowledgment and Insert Count Increment are `QPACK_DECODER_STREAM_ERROR`, since we never reference the dynamic table.
- `Sources/sws-bench/QPACKBench.swift`: `encode`/`decode`/`run` for a 10-field Safari request, ns per section, exposed but not wired into `main`. `SWSBench` gains the `QPACK` dependency (one-line `Package.swift` change).

## Gotchas

- Swift 6.4.2 miscompiles a `throws(QPACKError)` closure passed to a `rethrows` API such as `Array.withUnsafeBytes`: the error that comes out is garbage (`Code()`, `Reason.V()`). Inside such closures, use untyped `{ raw in try ... }` or catch inside the closure. The library avoids the pattern: none of its closures throw.
- `.whenShorter` Huffman-codes `/index.html` (8 bytes instead of 11), so the B.1 vector only matches with `huffman: .never`.
- Field section size exceeding the limit is reported as `.decompressionFailed` with reason `.fieldSectionTooLarge`. The HTTP/3 layer may prefer to answer it with a 431.
- Follow-ups: wire `sws-bench qpack` into `main` and record ns plus allocation counts once the harness can count allocations; switch name lookup to #0074's well-known header IDs and decode into `HTTPFields` once those exist in `HTTPCore`.
