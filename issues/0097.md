# 0097 — QPACK static-table encoder and decoder handle header blocks without a dynamic table

| | |
|---|---|
| **Status** | open |
| **Module** | QPACK |
| **Platform** | macOS |
| **First seen** | 2026-11-11 |

## Description

ROADMAP §6 starts HTTP/3 with QPACK using the 99-entry static table and literals only, advertising `SETTINGS_QPACK_MAX_TABLE_CAPACITY = 0`, so request streams share no mutable compression state.

## Scope

- Static table (RFC 9204 Appendix A) with name and name-value lookup via the well-known header IDs from #0074.
- Decoder: encoded field section prefix (Required Insert Count must be 0, otherwise `QPACK_DECOMPRESSION_FAILED`), indexed static, literal with static name reference, literal with literal name, never-indexed (N) bit surfaced; header list size enforced incrementally.
- Encoder: static indexed or static-name literal when possible, Huffman when shorter, never-indexed for `authorization`, `cookie`, `set-cookie`.
- Encoder/decoder stream instructions parsed and validated (peer may send them even when our capacity is 0; inserts beyond capacity are `QPACK_ENCODER_STREAM_ERROR`).

## Acceptance criteria

- RFC 9204 Appendix B.1 (literal field line with name reference) example encodes and decodes byte-for-byte; static-only field sections round-trip for a corpus of real browser request headers.
- A field section with non-zero Required Insert Count fails with `QPACK_DECOMPRESSION_FAILED`.
- `sws-bench qpack` records ns per 10-field decode and 0 allocations into reused `HTTPFields` storage.
