# 0005 — ExitHandler can resume its continuation twice or miss a termination that happens before wait()

| | |
|---|---|
| **Status** | open |
| **Module** | Lifecycle |
| **Platform** | macOS |
| **First seen** | 2026-09-12 |

## Description

`ExitHandler` (`Sources/SwiftWebServerCore/ExitHandler.swift`) never clears `continuation` after resuming it, so a second `terminate`, `interrupt`, or `resume` call resumes the same `CheckedContinuation` again. That is a fatal "SWIFT TASK CONTINUATION MISUSE" crash. Separately, if `terminate` runs before `wait()` has stored a continuation, the request is dropped and `wait()` later suspends forever.

## Steps to reproduce

1. In a test, call `await handler.terminate()` twice while a task is suspended in `wait()`, and observe the crash.
2. In a test, call `await handler.terminate()` before `wait()`, and observe that `wait()` never returns.

## Expected behavior

The first exit request wins, later requests are no-ops, and an exit requested before `wait()` makes `wait()` return (or throw) immediately.

## Actual behavior

A double resume crashes. An early exit request is lost.

## Notes

The listener failure path (`HTTPServer.swift:64-68`) calls `terminate()` from a detached `Task`, and it can race with `wait()` at `HTTPServer.swift:50`. Model the state as `.waiting(continuation) / .finished(Result)` and set it before resuming.
