## Description

This is the parity cut-over. `http-config.json` decoding fails unless every key is present (#0023), startup failures are swallowed (#0004 part), and the docs claim Linux support and behaviour the server does not have (#0026). Move the executable onto the new stack, delete `Legacy`, and make the docs true.

## Scope

- `ConfigFile` target: decode `http-config.json` with every key optional and documented defaults (#0023); unknown keys warn; validation errors name the key; builds `ServerConfiguration` and the component list.
- CLI: `swift run SwiftWebServer [--config path]` builds `Server` with HTTP1 and the configured components; bad config exits 1 with a message (#0004 part).
- Delete the `Legacy` and `LegacyTests` targets once every legacy bug repro (#0003–#0025) exists as a test against the new stack.
- Fix `docs/README.md`/`docs/PROJECT.md`/`docs/TODO.md`/`docs/MIDDLEWARE.md` claims and the `scripts/run.sh`, `scripts/sigint.sh`, `scripts/sigterm.sh`, `scripts/build.sh` scripts (#0026); macOS 15+ only, no Linux claim.
- Record the M4 benchmark run against the legacy baseline.

## Acceptance criteria

- A config with only `{"port": 0}` starts the server with defaults; a config with a wrong type exits 1 naming the key.
- `swift test` includes a test per legacy issue #0003–#0025 repro and all pass; `Sources/Legacy` no longer exists.
- `swift run -c release sws-bench --compare docs/benchmarks/m0-legacy-baseline.json` shows throughput above baseline and no regression over 10%.
- `scripts/run.sh` then `scripts/sigterm.sh` starts and stops the server cleanly.
