## Description

This is the parity cut-over. `http-config.json` decoding fails unless every key is present (#0023), startup failures are swallowed (#0004 part), and the docs claim Linux support and behaviour the server does not have (#0026). Move the executable onto the new stack, delete `Legacy`, and make the docs true.

## Scope

- `ConfigFile` target: decode `http-config.json` with every key optional and documented defaults (#0023); unknown keys warn; validation errors name the key; builds `ServerConfiguration` and the component list.
- CLI: `swift run SwiftWebServer [--config path]` builds `Server` with HTTP1 and the configured components; bad config exits 1 with a message (#0004 part).
- Delete the `Legacy` and `LegacyTests` targets once every legacy bug repro (#0003–#0025) exists as a test against the new stack.
- Fix `docs/README.md`/`docs/PROJECT.md`/`docs/TODO.md`/`docs/MIDDLEWARE.md` claims and the `scripts/run.sh`, `scripts/sigint.sh`, `scripts/sigterm.sh`, `scripts/build.sh` scripts (#0026); macOS 15+ only, no Linux claim.
- Record the M4 benchmark run against the legacy baseline.

## Acceptance criteria

- A config with only `{"port": 0}` starts the server with defaults; a config with a wrong type exits 1 naming the key.
- `swift test` includes a test per legacy issue #0003–#0025 repro and all pass; `Sources/Legacy` no longer exists.
- `swift run -c release sws-bench --compare docs/benchmarks/m0-legacy-baseline.json` shows throughput above baseline and no regression over 10%.
- `scripts/run.sh` then `scripts/sigterm.sh` starts and stops the server cleanly.

## Root cause

The shipped executable still ran the legacy server: `HTTPConfig` used the synthesized `Decodable` initializer, so every key was required (#0023). `main.swift` wrapped only the creation of a `Task` in `do/catch`, so startup errors were dropped and the process hung in `dispatchMain()` (#0004). The docs described behaviour the code never had (#0026).

## Fix

- `ConfigFile` (Foundation, startup only; now depends on HTTP1, HTTPServer and StaticFiles):
  - `ConfigFile.load/parse` reads JSON into `ServerSettings`, which documents a default for every key: host 127.0.0.1, port 8080, root `Public`, index, mimeTypes, defaultMimeType, blockList, blockDotfiles, caching, maxConnections 1024, maxBodySize 10 MiB, timeouts, drainTimeout, transport bsd, and errorPages.
  - Unknown keys, including nested ones, add warnings. A wrong type or range throws `ConfigFileError` with the dotted key.
  - Legacy aliases are accepted: `path`, `defaultIndex`, `maxRequestSize`, `keepAliveTimeout`, and the array form of `mimeTypes`. `enableETags` and `enableCompression` warn that they have no effect.
  - `tls` and `accessLog` are reserved. They pass through in `ConfigFile.reserved` with a warning, ready for #0087/#0090.
  - `ServerSettings+Components` maps the settings to `ServerConfiguration`, `HTTP1Configuration` and `StaticFilesConfiguration`. `makeHandler()` builds the chain with `MiddlewareBuilder`: `if let pages { ErrorPages }` in front of `StaticFiles`, which evaluates conditional requests itself. With `errorPages: false`, `ErrorPages` is not in the chain.
- `SwiftWebServer` is an `@main` async entry point:
  - Options: `--config`, `--root`, `--host` and `--port` override the config. Without `--config` it reads `$ROOT_PATH/http-config.json`, then `./http-config.json`, then the defaults.
  - Runs on a BSD or NW listener, prints `listening HOST:PORT`, and drains on SIGINT/SIGTERM through dispatch signal sources. These are the same pattern as `sws-bench serve`; the signal sources stay in the executable as CLAUDE.md requires.
  - Exits 1 with a stderr message on a config, root, error-page or bind error, and 2 on a usage error.
- `sws-bench serve --config` now parses with ConfigFile (only `loadConfig` changed).
- Deleted `Sources/Legacy`, `Tests/LegacyTests`, `LISTEN_HOST` and `legacySwiftSettings`.
- `Root/http-config.json` is rewritten in the new schema, with every default spelled out and the existing `Custom/404.html` and `Custom/405.html` used as error pages.
- Scripts:
  - `run.sh` and `bg.sh` use `--config Root/http-config.json` and pass extra arguments on.
  - `sigint.sh` and `sigterm.sh` take `PORT`.
  - `build.sh` and `commands.txt` are fixed.
  - `bench-compare.sh` no longer has the legacy row.
  - `bench-baseline.sh` now measures the shipped server against the M0 record (close and keep-alive) and adds a 1 GiB download RSS check.
- Docs: a new top-level `README.md` covers features, running, the configuration reference, architecture pointers and macOS 15+ only. `docs/PROJECT.md` and `docs/TODO.md` are marked historical. `docs/README.md`, `docs/benchmarks/README.md`, `ROADMAP.md` and `SERVER-COMPARISON.md` are updated.

## Gotchas

- `StaticFiles` is both an `HTTPHandler` and an `HTTPMiddleware`. As the last element of a builder block that is ambiguous, so `makeHandler()` passes it through a `some HTTPHandler` helper.
- `ChildProcess` cannot set environment variables, so `ParityTests` launch through `/usr/bin/env ROOT_PATH=… SwiftWebServer`. env execs the server, so the pid is still the server's.
- The default port stays 8080 (legacy, and `sigterm.sh`). `sws-bench serve --config` keeps port 0 as its default.
- The issue's `sws-bench --compare …m0-legacy-baseline.json` never existed. The comparison is the oha/sws-bench load run in `M4-cutover.md` against `M0-baseline.md`. M0 was recorded at load average 206, so the ratios overstate the gain.
- The oha small-file close row ran out of loopback ephemeral ports (TIME_WAIT), as noted in M0, so that row is limited by the client.
- The shipped executable has no TLS, HTTP/2 or HTTP/3 yet. The README says so.
