# 0023 — Config decoding fails unless every key is present despite declared defaults

| | |
|---|---|
| **Status** | open |
| **Module** | Config |
| **Platform** | macOS |
| **First seen** | 2026-09-12 |

## Description

`HTTPConfig` declares default values in its memberwise `init`, but decoding uses the synthesized `Decodable` initializer, which ignores those defaults. A config file missing any key (for example, `enableCompression`) fails to decode, and with #0004 the server then hangs. `PROJECT.md` documents the caching key as `"enable"`, but the code expects `"enabled"`, so the documented config fails too.

## Steps to reproduce

1. Remove `"enableCompression"` from `Root/http-config.json`.
2. Start the server.

## Expected behavior

Missing keys use the documented defaults.

## Actual behavior

`keyNotFound` is thrown during bootstrap.

## Notes

Implement `init(from:)` with `decodeIfPresent(...) ?? default`. The HTTP/2 and TLS config added in later phases depends on this.
