## Description

An HTTP/3 connection opens its control stream and QPACK encoder/decoder streams and validates the peer's (RFC 9114 §6.2, §7.2.4).

## Scope

- `H3Connection` state machine: on start, open control (type 0x00) with SETTINGS first, QPACK encoder (0x02) and decoder (0x03) streams.
- `UniStreamClassifier`: read the stream type varint; control, push (reject: we are a server), QPACK encoder/decoder, reserved/unknown types ignored with STOP_SENDING `H3_STREAM_CREATION_ERROR`.
- SETTINGS: `QPACK_MAX_TABLE_CAPACITY = 0`, `QPACK_BLOCKED_STREAMS = 0`, `MAX_FIELD_SECTION_SIZE` from limits, `ENABLE_CONNECT_PROTOCOL` when WebSockets are registered (#0111); duplicate control stream, missing SETTINGS first, duplicate setting identifiers, and HTTP/2 setting IDs are connection errors.
- Closing a critical stream is `H3_CLOSED_CRITICAL_STREAM`.

## Acceptance criteria

- In-memory tests (#0099) for each rule above, asserting the exact error code.
- `/opt/homebrew/opt/curl/bin/curl --http3-only -k -v` shows the connection established and SETTINGS exchanged (request handling may still 404 until #0101).

## Root cause

Feature work: the HTTP3 target had the frame codec (#0096) and QPACK (#0097) but no connection layer, so nothing opened our control stream, sent SETTINGS, or validated the peer's control and QPACK streams.

## Fix

- `H3Connection` (`Sources/HTTP3/H3Connection.swift`, commit 96a911e) is a pure value-type state machine, `mutating func handle(_:) -> Action`, with no I/O. It classifies peer streams: one control stream, one QPACK encoder and one QPACK decoder stream. A second one of any of these, or a client push stream, is `H3_STREAM_CREATION_ERROR`. Reserved and unknown types get `.ignoreStream(stopSendingCode: H3_STREAM_CREATION_ERROR)`. SETTINGS must come first (`H3_MISSING_SETTINGS`) and only once (`H3_FRAME_UNEXPECTED`). A closed or reset critical stream is `H3_CLOSED_CRITICAL_STREAM`. Push IDs are checked (CANCEL_PUSH above MAX_PUSH_ID, a decreasing MAX_PUSH_ID, an increasing client GOAWAY: `H3_ID_ERROR`). The first connection error wins, and requests arriving after it are rejected with `H3_REQUEST_REJECTED`.
- `H3Configuration.localSettings` sets QPACK_MAX_TABLE_CAPACITY 0, QPACK_BLOCKED_STREAMS 0 and MAX_FIELD_SECTION_SIZE (default 16 KiB). ENABLE_CONNECT_PROTOCOL is sent only when `enableConnectProtocol` is set, for #0111.
- Duplicate and HTTP/2 setting identifiers and bad boolean values are rejected by the existing `H3Settings` parser (`H3_SETTINGS_ERROR`), and frame-type rules by `H3FrameParser`. Their errors reach `H3Connection` as `.connectionError`.
- The runner (`HTTP3` / `H3ConnectionDriver` in `Sources/HTTP3/HTTP3.swift`, commit c699d16 with #0101) does the I/O. On connect it opens our control stream (type 0x00 + SETTINGS), QPACK encoder (0x02) and decoder (0x03) streams and keeps them open. It reads each peer uni stream's type with `UniStreamClassifier`, reads the control stream with `H3FrameParser(.control)`, and validates the QPACK streams with `QPACKEncoderStreamReader` / `QPACKDecoderStreamReader` (errors close with `QPACK_ENCODER_STREAM_ERROR` 0x201 / `QPACK_DECODER_STREAM_ERROR` 0x202). Ignored streams get `stopSending(H3_STREAM_CREATION_ERROR)`. Connection errors call `close(applicationError:)` with the H3 code.

## Gotchas

- The in-memory `reset` discards unread bytes, so a control stream reset before the server reads its type byte is never classified as a control stream. The reset test first completes a request round trip, so the server has seen the stream. A real peer has the same race; RFC 9114 only requires acting on streams whose type was read.
- Our control and QPACK stream objects must be kept alive (`localStreams`) for the whole connection. Releasing a `QUICStreamTransport` cancels it, and the peer would see `H3_CLOSED_CRITICAL_STREAM`.
- QPACK stream errors use the QPACK codes (0x200–0x202), not `HTTP3Error`, so `H3Connection` carries close codes as `UInt64`.
- `H3Settings` is only `Equatable`, so `H3Connection.Event` and `ControlFrame` are `Equatable` rather than `Hashable`.
- GOAWAY and graceful drain are #0102. Until then, a triggered shutdown signal closes the connection with `H3_NO_ERROR`.
