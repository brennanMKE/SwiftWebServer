## Description

This is the milestone where browsers and curl can fetch files over HTTP/2.

## Scope

- When a request's header block completes, add a child task to the connection's task group that calls `HTTPHandler.handle`.
- Response HEADERS carry `:status` and lowercase fields with connection-specific fields removed. END_STREAM is set on HEADERS when the body is empty (HEAD, 304).
- The body is iterated and sent as DATA frames no larger than the peer's MAX_FRAME_SIZE, with END_STREAM on the last frame, or trailers as a final HEADERS frame.
- A handler error before HEADERS are sent becomes a 500. After HEADERS it becomes `RST_STREAM(INTERNAL_ERROR)`.

## Acceptance criteria

- `curl --http2-prior-knowledge http://localhost:8080/` returns the index page.
- `curl --http2-prior-knowledge --parallel -Z` fetches 20 URLs over one connection. Verify with `-v` that they are multiplexed.

## Root cause

Feature work. The connection core (#0044) already built the dispatch and response path as the minimal request path for this issue: one child task per stream, HEADERS + CONTINUATION, DATA sized by the windows and MAX_FRAME_SIZE, `500` before HEADERS and `RST_STREAM(INTERNAL_ERROR)` after them. What was missing was the acceptance criteria and a few edge-case tests.

## Fix

- No behaviour change beyond #0048. That issue already made the handler receive `context.requestContext` (with connection-scoped observer values) and its request body.
- `Sources/HTTP2/HTTP2.swift`: the doc comment now describes the response path. Each stream's handler runs in its own child task. The head has `:status` first, lowercase names, no connection-specific fields, and `content-length` when the length is known. HEAD, 204 and 304 end the stream on HEADERS. DATA frames are no larger than the peer's MAX_FRAME_SIZE and both send windows. A handler error before HEADERS is a `500`; a body failure after them is `RST_STREAM(INTERNAL_ERROR)`.

## Verification

- `scripts/guarded.sh -t 900 -- swift test -j 2 --filter "H2CurlTests|H2ResponseTests"`: 11 tests passed.
- `H2CurlTests` (system curl 8.7.1 with nghttp2, `Server` with `[HTTP2(), HTTP1()]` on 127.0.0.1 port 0):
  - `curlGetsTheIndexPage`: `curl --http2-prior-knowledge http://localhost:<port>/` returns `Root/Public/index.html` byte for byte, with `200 2`.
  - `curlFetchesFiftyURLsOverOneConnection`: `curl -v -Z --parallel-max 50` fetches 50 URLs. All are `200 2`; `%{num_connects}` is 1 for one transfer and 0 for the other 49; the verbose log reports multiplexing; the server accepted one connection; and the handlers overlapped (peak in flight above 1, with each handler pausing 20 ms).
- `H2ResponseTests` (new, in memory):
  - `streamsRunConcurrently`: a stream whose handler waits does not hold up the next one;
  - `bodylessStatusEndsTheStreamOnHeaders`: 304 and 204 set END_STREAM on HEADERS and send no DATA;
  - `dataFramesUseThePeersMaxFrameSize`: with a 40,000-byte peer MAX_FRAME_SIZE, the largest DATA frame is exactly 40,000;
  - `bodyFailureAfterHeadersIsInternalError`: the stream is reset with `INTERNAL_ERROR` and the next stream is served;
  - `responseHeadIsMappedToHTTP2`.
- Existing tests still cover the `500` on a handler error, HEAD, `.stream` and `.file` bodies, flow-control waits, and header blocks that never interleave.

## Gotchas

- `HTTPResponse` has no trailer fields, so response trailers ("or trailers as a final HEADERS frame") cannot be sent yet. Adding them means extending the `HTTPCore` response type first.
- The curl tests serve files with a test handler, not `StaticFiles`, which is not a dependency of `HTTP2Tests`. Registering HTTP/2 in the shipped executable is still left for later (#0042 Gotchas).
