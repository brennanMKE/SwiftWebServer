## Description

The legacy `HTTPResponse` renders a `String`, converts to `Data`, emits headers in random dictionary order and omits `Date` (#0020). Serialize responses straight into the connection's output `ByteBuffer` from pre-rendered pieces.

## Scope

- `HTTP1Serializer.write(_ head: HTTPResponse, into: inout ByteBuffer)`: static status lines from `HTTPStatus`, header fields in insertion order, `Content-Length` rendered with integer-to-ASCII, chunked framing helper for `.stream` bodies of unknown length.
- `DateCache` in `HTTPCore`: renders the IMF-fixdate once per second into a fixed 29-byte buffer by fixed offsets (no `DateFormatter`); read without locking on the hot path (per-connection copy refreshed by timestamp compare or an atomic generation).
- `Date` added to every response (RFC 9110 §6.6.1) (#0020 part). The `Connection` header decision belongs to the connection state machine (#0080).
- Rejects CR/LF/NUL in header values at serialization in debug and a validated-path check in release (response splitting).

## Acceptance criteria

- Tests: byte-exact output for 200 with body, 204, 304, 404 and a chunked response; header order preserved; `Date` matches the RFC 9110 format and changes after one second (injected clock).
- `sws-bench serialize` shows < 100 ns and 0 allocations for a 10-header response, committed to `docs/benchmarks/`.

## Root cause

The legacy `HTTPResponse` built a `String`, converted it to `Data`, wrote headers in dictionary order and never sent `Date` (#0020). The new stack had response types (#0074) but nothing to put them on the wire.

## Fix

- `HTTP1Serializer<Clock>` (`Sources/HTTP1/HTTP1Serializer.swift`), one per connection, owning its `DateCache`. `write(_:into:context:)` reserves the output buffer once and writes the pre-rendered status line, the fields in insertion order (lowercase canonical names for well-known IDs), `date` unless present, `content-length` (integer-to-ASCII) or `transfer-encoding: chunked`, and `connection: keep-alive|close` from `HTTP1ResponseContext`. The connection decision itself stays with #0080; the context only carries it. Body rules: HEAD and 304 state the GET/200 length when known and send no content (a handler `content-length` passes through when the body is empty or chunked); 204 and 1xx carry no framing; 1xx writes only the handler's fields (so `101` keeps `connection: upgrade`); `.tunnel` writes no framing or `connection`. Returns `HTTP1BodyFraming` (`.complete`, `.contentLength(n)`, `.chunked`, `.tunnel`) so the runner knows what to send for `.file`, `.stream` and `.tunnel`.
- Response splitting: `write` debug-asserts that names are tokens and values have no CR/LF/NUL/control bytes, and that a handler `content-length` agrees with the body (or is absent where 204, chunked or tunnel forbids it). `writeValidated` is the release-checked path: it throws `HTTP1SerializationError` and writes nothing.
- `HTTP1ChunkedEncoder`: chunk header (lowercase hex), chunk end, whole chunk (empty data writes nothing so it cannot end the body), last chunk with or without trailers.
- `DateCache<Clock>` and `IMFFixdate` (`Sources/HTTPCore/DateCache.swift`): IMF-fixdate by Hinnant's `civil_from_days` and fixed offsets, no Foundation. **Per-connection value, not shared:** no lock or atomic on the hot path and no cache line shared between cores; the cost is one ~24 ns render per connection per active second. `SystemWallClock` reads `clock_gettime(CLOCK_REALTIME)` only when the current second has ended, detected by comparing `mach_continuous_time()` ticks (about 4 ns, counts through sleep) with a deadline computed at the last read; an NTP step is noticed at the next second boundary. Tests inject a `WallClock`.
- `ByteBuffer.withWriter(reservingCapacity:_:)` (`Sources/HTTPCore/ByteBuffer+Writer.swift`): one uniqueness/capacity check, then bounds-checked appends with inline overlapping-word copies up to 32 bytes. This took the 10-header serialize from 245 ns to about 105 ns.

## Gotchas

- The 10-header target (< 100 ns) is met on the minimum but not reliably on the median on a loaded machine; numbers swing ±30% with other agents building. Re-measure on an idle machine at milestone end. Per-field cost is about 6 ns; the next step would be retain/release in the field-array walk, not copying.
- Benchmark numbers are not yet written to `docs/benchmarks/`; the M1 milestone record is left to the orchestrator so parallel M1 workers do not collide on one file.
- Appending through `ByteBuffer.append` per piece costs a uniqueness check plus a `memcpy` call each time (about 4 per field); that was half the serializer's time. Use `withWriter` for many small appends.
- Generic types cannot have static stored properties, so `DateCache` uses local `StaticString`s for name tables; `Darwin` is an internal import in `HTTPCore`, so `SystemWallClock`'s methods cannot be `@inlinable` (one direct call per response).
- Field names go out lowercase (valid per RFC 9110 §5.1). HTTP/1.0 clients cannot read chunked responses; #0080 must not choose `.stream(length: nil)` framing for them (close-delimited instead).
