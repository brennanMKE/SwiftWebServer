## Description

`enableCompression` is parsed but never used (#0024 part). Add an opt-in compression middleware that uses Apple's Compression framework (no package dependency).

## Scope

- Parse `Accept-Encoding` with q-values; support `gzip` and `deflate` (and `br` only if available in the system framework without dependencies).
- Compress only compressible MIME types above a size threshold; skip `206`, `304`, HEAD and already-encoded bodies; add `Vary: Accept-Encoding`; streamed bodies compressed incrementally.
- ETags of compressed variants are weakened or suffixed so validators stay correct.
- The deflate primitive is reusable by permessage-deflate (#0110).

## Acceptance criteria

- `curl --compressed -v` shows `Content-Encoding: gzip` and the decompressed body equals the file; a 206 response is not compressed.
- `sws-bench` shows no change (< 2%) with the component unregistered.

## Root cause

New feature. `enableCompression` was parsed and ignored (#0024); nothing produced a
`Content-Encoding`.

## Fix

- **`Compression` middleware (target Compression):** after `next`, encodes responses whose
  `Content-Type` matches a configurable allowlist (`text/*`, JSON and `*+json`, JavaScript, XML
  and `*+xml` incl. SVG, wasm, YAML/TOML, ttf/otf/eot, ico/bmp; `text/event-stream` refused),
  with a known length ≥ `minimumSize` (1024) or a stream. Skips `1xx`/`204`/`206`/`304`, `HEAD`
  (adds `Vary` only), existing `Content-Encoding`, `Cache-Control: no-transform`, and responses
  whose `Vary` already lists `Accept-Encoding` (negotiated by their producer). Adds
  `Vary: Accept-Encoding`, drops `Content-Length`/`Accept-Ranges`, and suffixes a strong `ETag`
  per coding (`-br`, `-gz`, `-df`; weak tags kept); a `GET` whose `If-None-Match` names the
  variant tag gets `304` from the middleware.
- **Negotiation (`AcceptEncoding`):** q-values in thousandths, `*`, `x-gzip`, `identity`
  (wins only with a higher explicit weight), q=0 refusals, malformed `q` ignored, multiple field
  lines; equal weights prefer `br` > `gzip` > `deflate`. One pass over the bytes, tokens compared
  as packed integers, no allocation.
- **Bodies:** `.bytes` one-shot into a buffer smaller than the input (identity when it would not
  shrink); `.stream` and `.file` become `.stream(length: nil)` compressed incrementally through
  `CompressingBodyWriter` in `chunkSize` (16 KiB) pieces, each awaited on the connection's writer
  (backpressure; chunked on HTTP/1.1, close-delimited on 1.0); files are read with `pread` in
  `chunkSize` pieces.
- **Codecs (system libraries, zero package dependencies):** `libz` (`import zlib`) for gzip and
  deflate (`DeflateEncoder`/`DeflateDecoder`, raw/zlib/gzip framing, `Z_SYNC_FLUSH` for
  permessage-deflate #0110), zlib encoders pooled per coding; Apple `libcompression` for Brotli
  (`BrotliStream`), resolved with `dlopen`/`dlsym` because this target's module name shadows the
  SDK's `Compression` Clang module. `ContentCodec.encode`/`decode` for one-shot use and tests.
- **StaticFiles precompression:** `StaticFilesConfiguration.compression` renders `br` and `gzip`
  variants of cached small files once (gzip level 9), or takes `file.br`/`file.gz` sidecars
  (regular files, not links, not older than the file; large sidecars sent from the open file;
  `precompressedSidecars`). Each request picks a variant from `Accept-Encoding` (equal weights
  → the smallest), conditional requests are evaluated against the variant's tag, `Range` is
  served from the unencoded file. Variants and the unencoded response carry `Vary`; large files
  without sidecars do not, so the middleware streams them. Adds a dependency edge
  StaticFiles → Compression.
- **ConfigFile/executable:** `"compression": true | {encodings, minimumSize, level,
  precompressionLevel, mimeTypes, precompress, sidecars}`; legacy `enableCompression` is an
  alias. `makeHandler()` registers `Compression` outermost only when enabled.
- **sws-bench:** `Compression.*` micro cases (variant hits, 304, negotiation, dynamic per coding
  and level, skips). Docs: `docs/MIDDLEWARE.md`, README config table,
  `docs/benchmarks/M6-compression.md`.

  skip rules (types, size, 206/304/204, HEAD, existing encoding, upstream `Vary`, no-transform,
  incompressible bytes), ETag suffixing and 304 on the variant tag, pooled and concurrent
  encoders, an 8 MiB stream with no piece above `chunkSize` and output before the producer

  Range, HEAD, smallest at equal weight, sidecars incl. stale/linked/large/off), and
  `curl --compressed` through `ChildProcess` against a real server on loopback port 0
  (`Content-Encoding: gzip`, decoded body equals the file, a 206 not compressed, 304 for the
  variant tag, a 4 MiB file streamed chunked and over HTTP/1.0, a sidecar on the wire).
- ConfigFile (26) and StaticFiles tests pass; full `swift test -j 2` passes (about 1,280 tests,
  the 4 known HTTP/3 issues unchanged).

## Gotchas

- The target is named `Compression`, the same as the SDK's Clang module for `compression.h`:
  `import Compression` inside it imports itself. Brotli is reached with `dlsym`; keep the
  `compression_stream` mirror in `Brotli.swift` in step with the header.
- Apple's Brotli encoder is quality 2 only. On the benchmark page gzip level 9 (10,256 B) beats
  it (12,101 B), so the cache sends gzip to `br, gzip` clients; ship `.br` sidecars made at
  quality 11 to get Brotli's real advantage.
- `deflate` is not cached in StaticFiles (it would win every size tie against gzip by 12 bytes
  of framing); deflate-only clients get the static file unencoded, dynamic responses still get
  `deflate`.
- gzip level 6 is 4.5× slower than level 4 on markup with a small vocabulary (long hash chains)
  for 5% smaller output; the dynamic default is 4.
- Sidecars are looked up when a file enters the cache; replacing only a sidecar is seen when the
  file changes or the entry is evicted. A sidecar older than its file is ignored.
- A compressible dynamic response to a client that accepts no coding still pays a header copy
  (4 allocations) to add `Vary`.
