# 0116 — Open WebSockets close with 1001 when the server shuts down

| | |
|---|---|
| **Status** | open |
| **Module** | HTTPCore / HTTP1 / WebSockets |
| **Platform** | macOS |
| **First seen** | 2026-11-11 |

## Description

Follow-up from the #0109 Gotchas. The `.tunnel` closure gets no shutdown signal, so a draining server cannot tell open WebSockets to close. They end only when the drain deadline cancels the connection task, and clients see an abrupt end (1006) instead of a close handshake with 1001 Going Away (RFC 6455 §7.4.1).

## Expected behavior

When the server starts draining, every open WebSocket session sends Close 1001, completes the close handshake, and its connection ends before the drain deadline.

## Scope

- Pass the connection's `ShutdownSignal` into the `.tunnel` closure (a small context value next to the transport), from HTTP/1.1 and from HTTP/3 (#0111).
- `WebSocket.run(over:)` takes an optional shutdown signal and starts the close handshake with 1001 when it triggers.
- Test: in-memory and with `URLSessionWebSocketTask`, triggering the server's shutdown makes the client see 1001 and the server finish well before its drain deadline.
