# 0027 — Define a Transport protocol with an AsyncSequence of inbound bytes and async writes

| | |
|---|---|
| **Status** | open |
| **Module** | Transport |
| **Platform** | macOS |
| **First seen** | 2026-09-12 |

## Description

Protocol code should never touch `NWConnection` directly. Introduce a `Transport` protocol that is the only boundary between the network and the HTTP/1.1 and HTTP/2 codecs. This lets every codec be tested with an in-memory transport and lets the Network API be swapped later (see `docs/HTTP2.md`, Decisions).

## Scope

- `protocol Transport: Sendable` with `inbound: some AsyncSequence<ArraySlice<UInt8>, any Error>`, `negotiatedProtocol: String?`, `func write(_:) async throws`, and `func close() async`.
- `InMemoryTransport.makePair()` for tests, with writes on one side appearing as inbound on the other.
- The design must not use Combine or unstructured tasks.

## Acceptance criteria

- Tests round-trip bytes through an in-memory pair, including a close on each side and error propagation.
