## Description

Protocol selection must happen once per connection and be pluggable so HTTP/2, HTTP/3 and future protocols register instead of editing the core. Add ALPN and the registry from ROADMAP §5.2.

## Scope

- `Server(protocols: [HTTP1.self, ...])` registry: ALPN tokens collected from registered `ConnectionProtocol`s in preference order and passed to `sec_protocol_options_add_tls_application_protocol`.
- Negotiated ALPN read with `sec_protocol_metadata_get_negotiated_protocol` into `ConnectionInfo`; dispatch to the matching protocol; no ALPN → HTTP/1.1.
- Cleartext sniffing: buffer the first bytes and ask each protocol's `matchesCleartextPreface(_:)` (`.match`, `.noMatch`, `.needMoreBytes`); default HTTP/1.1; sniffed bytes are handed to the chosen protocol without copying.
- The ALPN half of #0058; routing `h2` to `HTTP2Connection` stays in #0058 under M12.

## Acceptance criteria

- Tests register a fake protocol with ALPN token `x-test` and a fake preface and assert routing for TLS (via an NW TLS client offering `x-test`) and for cleartext, including a preface split over two reads.
- `curl -v --http1.1 -k https://localhost:8443/` shows `ALPN: server accepted http/1.1`.

## Root cause

`ProtocolRegistry` (#0079) already chose by ALPN, a single protocol, or a cleartext sniff, but
nothing collected the tokens for a TLS listener, a TLS connection with no or an unknown ALPN
token was closed instead of served as HTTP/1.1, and the sniff loop had no timeout: a client
that connected and sent nothing held the connection until it gave up (the gap the #0082 report
flagged).

## Fix

- `ProtocolRegistry.alpnTokens`: the registered protocols' tokens in preference order, without
  duplicates, for `TLSConfiguration(alpn:)`. `h2` is offered only once Track B registers HTTP/2.
- `select(alpn:secure:preface:)`: on TLS (`ConnectionInfo.isSecure`) the negotiated token picks
  the protocol; an absent or unknown token falls back to the protocol listing `http/1.1`.
  Cleartext behaviour is unchanged.
- `ServerConfiguration.sniffTimeout` (default 10 s, the HTTP/1.1 header timeout) bounds
  sniffing. The timer is a sibling task in a task group that exists only while sniffing
  (cleartext, more than one protocol); the connection is closed with `.timeout`.
- `sws-bench serve --tls [--identity FILE] [--password PW]`: HTTPS on a Network.framework TLS
  listener offering the registry's tokens, defaulting to the test identity; a bad identity exits
  1 naming the file.

## Gotchas

- The registry does not configure the listener: the listener is built before the `Server`, and
  NW fixes its TLS options at creation, so the caller passes `ProtocolRegistry(protocols).alpnTokens`
  into `TLSConfiguration(alpn:)` (as `sws-bench serve --tls` does).
- With only HTTP/1.1 registered nothing is sniffed, so the sniff timeout never runs; the
  HTTP/1.1 idle and header timeouts (#0082) cover silent clients there.
- The acceptance criterion's `localhost:8443` is port 0 in tests (AGENTS.md).
