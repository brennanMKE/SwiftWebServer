# 0082 — Header, idle and body timeouts send 408 and the server drains gracefully

| | |
|---|---|
| **Status** | open |
| **Module** | HTTP1 / HTTPServer |
| **Platform** | macOS |
| **First seen** | 2026-11-11 |

## Description

`keepAliveTimeout` is parsed but ignored, so idle and slow-header connections live forever (#0012). Add per-phase deadlines and a graceful drain on shutdown.

## Scope

- `Deadline`-based timeouts in the HTTP/1.1 runner: header-read timeout (slowloris), keep-alive idle timeout, body-read inactivity timeout; values from configuration with documented defaults.
- Header or body timeout mid-request → `408 Request Timeout` + close; idle timeout between requests → silent close.
- Graceful drain: on `ServerLifecycle.draining`, idle connections close immediately, in-flight requests finish and their connection closes after the response (`Connection: close`), and anything left at the drain deadline is cancelled.
- Timeouts implemented as children of the connection's task group or a deadline checked by the runner, not unstructured tasks.

## Acceptance criteria

- In-memory tests with an injected clock: slow-header client gets 408 and is closed; idle keep-alive connection closed at the timeout; drain lets an in-flight streamed response finish and refuses new requests.
- Socket test: `nc localhost <port>` sending a partial request line is closed after the header timeout.
- SIGTERM during a large-file `curl` download completes the download and the process exits 0 within the drain deadline.
