## Description

The server must serve port 8080 and 8443 at once with a shared lifecycle (#0059).

## Scope

- Multiple listener children in the server task group; each listener has its own protocol registry view (TLS listeners use ALPN, cleartext sniffs).
- Startup fails as a whole if any configured listener fails to bind; shutdown drains both.
- Shared connection limit across listeners, with per-listener counts in metrics.

## Acceptance criteria

- An integration test binds cleartext and TLS on port 0, fetches from both with `curl` (`-k` for TLS), then sends SIGTERM to the process and observes exit 0.
- If the TLS port is already in use, the process exits 1 and the cleartext port is not left listening (`lsof -i :<port>` empty).

## Root cause

`Server<Listener, Handler>` served one listener type through one accept loop shape, so the
cleartext BSD listener, the NW TLS listener and the QUIC listener could not run under one
server, and `Server` had no path for multiplexed connections at all (#0102 Gotchas). The
config file reserved `tls` without using it, and the executable bound one cleartext listener.

## Fix

- **HTTPCore:** `MultiplexedTransportListener` (listen, connections, close, `connectionInfo`,
  `refuse`), the QUIC counterpart of `TransportListener`. `QUICListener` conforms
  (NetworkTransport).
- **HTTPServer:** `ServerListener` erases a listener to `.byteStream` (served through the
  `ProtocolRegistry`, ALPN for TLS, sniffing for cleartext) or `.multiplexed` (served by its
  `MultiplexedConnectionProtocol`, e.g. `HTTP3`). `Server<ServerListener, H>` takes any mix;
  `Server<SomeListener, H>` still works (the old initializers moved to an extension
  `where Listener: TransportListener`). Each listener has its own accept loop in the server's
  task group, one generic loop for both kinds, sharing the connection limit (backpressure or
  refuse), the drain deadline and the `ShutdownSignal`. HTTP/3 connections get the same signal,
  so a shutdown sends GOAWAY. Listeners bind in order; if one fails, the bound ones are closed
  and `run()` throws (startup fails as a whole). `.byteStream(name:make:)` and
  `.multiplexed(name:protocol:make:)` create the listener at bind time from a `BindContext`:
  the addresses bound so far (QUIC can take the TLS listener's port number when that was 0)
  and the ALPN tokens to offer (the registry's `alpnTokens` for byte streams, the protocol's
  own for multiplexed ones), which is how a TLS listener now gets its ALPN list from the
  registry. `listenerStatistics` gives per-listener name, address, accepted, open and refused.
- **ConfigFile:** `tls` (`identity`, `password` or `passwordEnv`, `port` default 8443,
  `enabled`) and `http3` (`true`, or `enabled`, `port` defaulting to the TLS port number,
  `altSvcMaxAge` default 86400). Both are off by default; `http3` needs `tls`.
  `ServerSettings.validate()` also checks, after command-line overrides, that the TLS port is
  not the cleartext port. `accessLog` stays reserved.
- **Executable:** builds cleartext, then `https`, then `h3` listeners from the config (identity
  loaded in memory once and shared by TLS and QUIC), prints `listening HOST:PORT` for
  cleartext and `listening HOST:PORT (https)` / `(h3)` for the others, and links `HTTP3`
  through the `HTTP3` package trait (`#if HTTP3`). HTTP/3's `closeLinger` is raised to the
  drain timeout (see Gotchas). `Root/http-config.tls.json` points at `.test-identity/`.

## Gotchas

- **HTTP/3 drain and slow readers.** `send` on a QUIC stream returns once Network.framework
  has the bytes, not once the peer has them. With the default `closeLinger` (1 s) a
  rate-limited `curl --limit-rate 8M` lost the last 16 KiB of a 24 MiB download: the server
  finished writing, lingered 1 s and sent CONNECTION_CLOSE while NW still buffered the tail
  (`curl: (56) ngtcp2_conn_writev_stream returned error: ERR_CLOSING`). The executable now sets
  `closeLinger` to the drain timeout; a client that closes first (curl does as soon as its
  transfer is done) still ends the wait at once. An idle HTTP/3 client that keeps its
  connection open after GOAWAY now holds the shutdown until the drain deadline. A real fix
  needs a "peer acknowledged everything" signal from NW, which it does not expose.
- QUIC already reports `negotiatedALPN == "h3"` in `QUICConnection.info`; `HTTP3.run` fills it
  in only as a fallback (#0103).
- `ChildProcess.waitForLine`'s parse closure runs under the child's state lock, so it must not
  read `child.stdout` (that re-enters the lock and crashed the test process, leaving four
  orphaned servers). Wait for one line, then read `stdout`.
- `QUICListener` binds with `allowLocalEndpointReuse = true`, so a UDP port already in use may
  not fail the bind the way a TCP port does; the "port in use" check covers the TLS port.
- `--port` overrides only the cleartext port; TLS and HTTP/3 ports come from the config (tests
  set them to 0).
- The ALPN list comes from the registry only for listeners made with `.byteStream(name:make:)`.
  A `TCPListener` built ahead of time still fixes its `TLSConfiguration(alpn:)` itself, because
  NW copies the TLS options when the listener is created.
- `redirectToHTTPS` from legacy #0059 was not built; it was not in this issue's scope.
