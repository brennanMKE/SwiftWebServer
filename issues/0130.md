## Description

Found while writing the choosing-components guide. (1) The `WebSockets` package trait does nothing: the executable doesn't link the `WebSockets` target. (2) `TLSNegotiatedHTTP2` is internal to the executable, so a custom server that registers `[HTTP2, HTTP1]` sniffs the first bytes of every cleartext connection instead of using ALPN on TLS only.

## Scope

- Either wire the `WebSockets` trait into the executable (and ConfigFile) or remove the trait.
- Move the TLS/ALPN-selected HTTP/2 wiring into a public library type (in `HTTPServer` or `HTTP2`) so custom servers get the same behavior; update `docs/guide/choosing-components.md` and `Examples/custom-server`.

## Acceptance criteria

- `Examples/custom-server` uses the public type; a test shows cleartext connections aren't sniffed when only TLS should negotiate h2.

## Relation

- **Milestone:** M17 follow-ups (deployment readiness)
- **Blocked by:** none
- **Blocks:** none

## Root cause

(1) The ALPN-only HTTP/2 wiring from #0119 was written as an internal type in the executable
target, so library users could only register `[HTTP2, HTTP1]`, which makes the registry sniff
(and wrap in a replay transport) every cleartext connection. (2) The `WebSockets` trait was
declared in #0069 as a placeholder and never wired: the executable has no in-process WebSocket
endpoints (those need Swift handler code), and WebSocket proxying is part of `Proxy`.

## Fix

- New public `TLSNegotiated<Preferred, Fallback>: ConnectionProtocol` in `HTTPServer`
  (generic, so HTTPServer gains no HTTP2 dependency and the hot path stays existential-free).
  It offers `Preferred`'s then `Fallback`'s ALPN tokens, runs `Preferred` only on a TLS
  connection that negotiated one of its tokens, and sniffs like `Fallback`. Registered alone,
  cleartext connections go straight to `Fallback`. Usage:
  `TLSNegotiated(HTTP2(), fallback: HTTP1())`.
- The executable's `ServerProtocols` uses it; the internal `TLSNegotiatedHTTP2` is gone.
- `WebSockets` trait removed (the honest option): there is no config-level way to define an
  in-process WebSocket endpoint, so a trait plus a ConfigFile key would have nothing to
  switch. Proxied WebSockets (`"websocket": true`) are unaffected.
- `Examples/custom-server` registers `TLSNegotiated(HTTP2(), fallback: HTTP1())` and links
  `HTTP2`; `docs/guide/choosing-components.md` documents the type, the h2c alternative, and
  why there is no WebSockets trait.

## Verification

- `swift build -j 2 --build-tests` — clean.
- `scripts/guarded.sh -t 600 -- swift test -j 2 --skip-build --filter "TLSNegotiatedTests|H2PrefaceTests"` —
  16 tests passed, including the 5 new `TLSNegotiatedTests`: `offersBothTokensPreferredFirst`,
  `tlsWithH2RunsHTTP2`, `tlsWithoutH2RunsHTTP1`, `cleartextPrefaceIsNotHTTP2` (the h2
  prior-knowledge preface on cleartext reaches HTTP/1.1), and `cleartextIsNotSniffed` (the
  fallback receives the raw `InMemoryTransport`, whereas `[HTTP2(), …]` hands it the sniffing
  replay wrapper).
- `scripts/guarded.sh -t 900 -- swift test -j 2` — 1616 tests across 21 runs, all passed.
- `cd Examples/custom-server && swift build -j 2` — Build complete.

## Files changed

- `Sources/HTTPServer/TLSNegotiated.swift` — new public `TLSNegotiated` protocol wrapper.
- `Sources/SwiftWebServer/ServerProtocols.swift` — uses `TLSNegotiated`; internal type removed.
- `Tests/HTTP2Tests/TLSNegotiatedTests.swift` — new tests (HTTP2Tests already links HTTPServer and HTTP1).
- `Package.swift` — `WebSockets` trait removed from `traits` and the default set.
- `Examples/custom-server/{Package.swift,README.md,Sources/MySite/MySite.swift}` — HTTP2 product, `TLSNegotiated`.
- `docs/guide/choosing-components.md` — traits section, custom-server listing, HTTPS snippet and notes.
- `docs/ROADMAP.md` — §5 trait sentence no longer lists WebSockets.

## Gotchas

- `TLSNegotiated` must be the only byte-stream protocol to avoid sniffing; registered next to
  others, its `matchesCleartextPreface` is `Fallback`'s.
- Anyone building with `--traits WebSockets` now gets an unknown-trait error; the default
  trait set no longer names it.
