## Description

Implement GOAWAY (RFC 9113 §6.8) for both error handling and orderly shutdown.

## Scope

- A connection error sends `GOAWAY(lastProcessedStreamID, code, debugData)`, flushes the writer, closes the transport, and cancels the group.
- Graceful shutdown (triggered by `ServerLifecycle` entering draining (#0079) or the idle timeout) sends `GOAWAY(2³¹−1, NO_ERROR)`, waits for a PING round-trip, then sends the final `GOAWAY(lastStreamID)`. In-flight streams drain up to a deadline, and new streams above the last id are refused.
- A GOAWAY received from the peer stops new streams, lets existing streams finish, and then closes.

## Acceptance criteria

- A test starts a slow download, triggers server shutdown, and asserts that the download completes, a new stream is refused, and `run()` returns.

## Root cause

Feature work. The connection core (#0044) had three gaps:

- A connection error sent GOAWAY and closed the transport at once. There was no lingering close, so a peer with unread data in flight could see a TCP reset before it read the GOAWAY (#0044 Gotchas).
- A server drain sent a single GOAWAY with the highest stream seen, so a stream the client opened while that GOAWAY was in flight was silently dropped. Streams above the bound were ignored, not refused.
- A GOAWAY from the peer, and idle connections, were not handled.

## Fix

- **State machine** (`HTTP2Connection`):
  - `.shutdown` now sends the first GOAWAY, `gracefulGoaway(2³¹−1, final: false)`. Streams are still accepted after it.
  - `.finishShutdown` sends the final `gracefulGoaway(last processed, final: true)` and bounds the stream table.
  - A GOAWAY from the peer is answered with the final GOAWAY right away.
  - After the final GOAWAY, HEADERS opening a stream above the bound get `RST_STREAM(REFUSED_STREAM)` (§8.7: safe to retry). Other frames on those streams are ignored. A later connection error keeps the lower last-stream-ID.
- **Driver** (`HTTP2ConnectionDriver.shutDownGracefully`):
  - When `context.shutdown` triggers (the `ServerLifecycle` drain), or after `idleTimeout` with no stream running: first GOAWAY, then a PING round trip (`ping(timeout:)` from #0050, at most `shutdownPingTimeout`), then the final GOAWAY.
  - The connection closes when the last stream at or below the bound ends.
  - With `drainTimeout` set, the streams still running at the deadline are cancelled. Each resets itself with `CANCEL` (#0051), and the last one to end closes the connection. Without it, the server's drain deadline cancels the connection as before.
- **Connection errors.** A connection error still sends `GOAWAY(last processed, code, debug data = code name)`. Now the request bodies end and the stream tasks are cancelled at once, before the lingering close.
- **Lingering close.**
  - Writer: after flushing the last frames on a non-abortive close, it half-closes (`send(endOfStream: true)`, so the peer reads end of stream after the GOAWAY). It then waits up to `lingerTimeout` for the reader to finish before it closes the transport.
  - Reader: after a connection error it keeps reading and discarding, up to `maxLingerSize`. After a graceful close it keeps processing frames until the peer closes.
  - When the peer closed first, there is no wait.
- **New `HTTP2Configuration` settings:**

  | Setting | Default |
  |---|---|
  | `shutdownPingTimeout` | 1 s |
  | `drainTimeout` | `nil` |
  | `idleTimeout` | `nil` |
  | `lingerTimeout` | 2 s |
  | `maxLingerSize` | 1 MiB |

- No `HTTPServer` change was needed: the server's drain already triggers `context.shutdown` and cancels connections at its deadline.

## Gotchas

- `idleTimeout` defaults to `nil`, so idle HTTP/2 connections stay open until the server drains. `ConfigFile` has no `http2.*` keys yet. They belong with registering HTTP/2 in the executable, which is left for later.
- A graceful shutdown waits up to `shutdownPingTimeout` (1 s) for the PING ACK. A server drain therefore takes at least one round trip per HTTP/2 connection, and up to 1 s for a client that does not answer PINGs.
- After the final frames the writer half-closes. Frames the reader produces while lingering (a PING ACK, say) are queued but never sent.
- The lingering close adds up to `lingerTimeout` before `run()` returns when a client keeps its side open after the GOAWAY. curl and nghttp2 close promptly.
