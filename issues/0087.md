## Description

There is no TLS (#0057). Load a server identity and add a TLS listener using `NWProtocolTLS`, configured inside `NetworkTransport`.

## Scope

- Identity loading from a PKCS#12 file with password (from config or environment) via `SecPKCS12Import`, or from the keychain by label; clear errors for a wrong password or missing file.
- `NWProtocolTLS.Options` with minimum TLS 1.2, `sec_protocol_options_set_local_identity`; TLS flag exposed on `ConnectionInfo`.
- Config keys for the TLS listener port, identity path and password source, all optional with defaults (TLS disabled when absent).
- Uses the identity from #0072 in tests.

## Acceptance criteria

- `curl -k https://localhost:8443/` and `curl --cacert TestIdentity/ca.pem https://localhost:8443/` return the index page.
- A `URLSession` test with a trust override for the test CA fetches a file over TLS.
- A wrong PKCS#12 password exits 1 with a message naming the identity file.

## Root cause

The new stack had no TLS: `TLSIdentity` (#0072) could import a PKCS#12 identity in memory, but
no listener used it, and `ConnectionInfo` had no TLS version.

## Fix

- `TLSConfiguration` (NetworkTransport): a `TLSIdentity` (or `init(pkcs12Path:password:)`,
  imported with `kSecImportToMemoryOnly`), minimum TLS 1.2 (Network.framework negotiates 1.3
  whenever offered), the ALPN list, an optional `ClientAuthentication` hook (verify block plus
  `sec_protocol_options_set_peer_authentication_required`; off by default) and a
  `handshakeTimeout` (10 s).
- `TCPListener(configuration:tls:)` layers `NWProtocolTLS` over TCP. Accepted connections are
  handed over after the handshake; `TCPTransport` fills `ConnectionInfo.isSecure`,
  `negotiatedALPN` and the new `tlsVersion` (`TLSVersion`, HTTPCore) from the TLS metadata.
- A failed handshake is logged (`os.Logger`, subsystem `SwiftWebServer`, category `TLS`),
  counted in `TCPListener.failedHandshakeCount`, and dropped. A per-connection timer on the
  listener queue resets connections still in the handshake after `handshakeTimeout`, so
  silent clients cannot hold pending-accept slots.
- `TLSClientConfiguration` and `TCPTransport.connect(host:port:configuration:tls:)`: an NW TLS
  client that pins the test certificate in-process (tests, tools).

## Gotchas

- Deviations from the scope above: no keychain-by-label loading (AGENTS.md forbids keychain
  access), tests use port 0 instead of 8443, and the TLS settings are `sws-bench serve` flags
  (`--tls --identity --password`, #0088), not config-file keys, because the shipped executable
  is not on the new stack yet. `curl --cacert` was not tested: the test certificate is a
  self-signed leaf (`CA:FALSE`), and clients pin it instead.
- No identity reload hook: NW copies the listener's parameters when the listener is created and
  has no public server-side per-handshake identity hook, so reloading means a new listener.
- A cleartext request on the TLS port fails the handshake at once (`.failed`, not `.waiting`).
  An unknown-only ALPN offer gets a `no_application_protocol` alert; no ALPN offer completes
  with `negotiatedALPN == nil`.
- With client auth required, a TLS 1.3 client without a certificate reaches `.ready` before the
  server rejects it; the client sees the connection end on its first receive.
