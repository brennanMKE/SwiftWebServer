## Description

Turn decoded header fields into an `HTTPRequest` and reject malformed requests (RFC 9113 §8.1.1, §8.2, §8.3). Pseudo-header and field validation lives in `HTTPCore` and is shared with HTTP/3 (#0101); whichever lands first creates it.

## Scope

- Exactly one each of `:method`, `:scheme`, and `:path` (non-empty; `*` only for OPTIONS), plus `:authority` and/or `host`. Pseudo-headers come before regular fields, and no unknown or response pseudo-headers are allowed.
- Field names must be lowercase and valid. Values must not contain CR, LF, or NUL, or leading or trailing whitespace.
- Connection-specific fields (`connection`, `keep-alive`, `proxy-connection`, `transfer-encoding`, `upgrade`) are rejected, and `te` is allowed only with the value `trailers`.
- `cookie` crumbs are joined with `"; "` for the handler.
- `content-length` must equal the total DATA length (checked in #0048).
- Malformed requests are stream `PROTOCOL_ERROR`s (RST_STREAM), not connection errors.

## Acceptance criteria

- One test per rule.

## Root cause

Feature work: the connection core (#0044) validated request heads with `PseudoHeaderValidator` only. Cookie crumbs reached the handler as separate fields, `content-length` was not parsed, and `host` was not compared with `:authority`.

## Fix

- `HTTP2RequestFieldSink` (`Sources/HTTP2/HTTP2Message.swift`) checks every decoded field in order:
  - through the shared `PseudoHeaderValidator` (HTTPCore, unchanged): pseudo-header presence, uniqueness, order, unknown and response pseudo-headers, `:path` rules, lowercase token names (an uppercase name is a stream `PROTOCOL_ERROR`), values without CR, LF, NUL or surrounding whitespace, connection-specific fields, and `te` other than `trailers`;
  - `content-length` must be a decimal number. It may repeat only with the same value, and it must be zero when HEADERS carries END_STREAM;
  - `host` sent with `:authority` must name the same authority, compared case-insensitively (§8.3.1).
- Cookie crumbs (§8.2.3) are joined with `"; "` into one `cookie` field. The joined field goes after the other fields. A single crumb is stored as it arrived.
- `head(endStream:)` returns the `HTTPRequest` and the declared `content-length`, or an `HTTP2MalformedRequest`. The driver answers a malformed head with `RST_STREAM(PROTOCOL_ERROR)`, never GOAWAY. Every field is still HPACK-decoded after the first violation.
- `HTTP2TrailerFieldSink` collects a trailer section (regular fields only) for #0048.

## Verification

- `scripts/guarded.sh -t 900 -- swift test -j 2 --filter H2RequestHeadTests`: 26 tests passed. Over a sink there is one test per rule: each missing pseudo-header, missing authority and host, duplicate, empty path, `*` without OPTIONS (and accepted with it), pseudo-header after a regular field, unknown and `:status` pseudo-headers, uppercase name, invalid name byte, six invalid values, five connection-specific fields, `te: gzip`, joined and single cookies, five invalid `content-length` values, conflicting values, `content-length` with END_STREAM, `host` mismatch (and a case-only difference accepted), and trailer rules. Over a connection, ten malformed requests each get `RST_STREAM(PROTOCOL_ERROR)` and the next request is served; a handler sees `a=1; b=2`.

## Gotchas

- The `content-length` check against the DATA total needs the body, so it is done in #0048. This issue parses the value and rejects a non-zero value on a HEADERS frame that ends the stream.
- `PseudoHeaderValidator` is unchanged, so HTTP/3 behaviour does not change. The HTTP/2-only rules (`content-length`, `host`, cookies) live in the HTTP/2 sink. HTTP/3 keeps cookie crumbs separate.
- Joining cookies copies the crumbs to the end of the request buffer. Appending a buffer's own bytes to itself may reallocate it once. This happens only when a request has two or more crumbs.
