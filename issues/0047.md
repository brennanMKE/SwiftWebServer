# 0047 — Validate request header fields and pseudo-headers and map them to HTTP message types

| | |
|---|---|
| **Status** | open |
| **Module** | HTTP2Connection / Semantics |
| **Platform** | macOS |
| **First seen** | 2026-09-12 |

## Description

Turn decoded header fields into an `HTTPRequest` and reject malformed requests (RFC 9113 §8.1.1, §8.2, §8.3).

## Scope

- Exactly one each of `:method`, `:scheme`, and `:path` (non-empty; `*` only for OPTIONS), plus `:authority` and/or `host`. Pseudo-headers come before regular fields, and no unknown or response pseudo-headers are allowed.
- Field names must be lowercase and valid. Values must not contain CR, LF, or NUL, or leading or trailing whitespace.
- Connection-specific fields (`connection`, `keep-alive`, `proxy-connection`, `transfer-encoding`, `upgrade`) are rejected, and `te` is allowed only with the value `trailers`.
- `cookie` crumbs are joined with `"; "` for the handler.
- `content-length` must equal the total DATA length (checked in #0048).
- Malformed requests are stream `PROTOCOL_ERROR`s (RST_STREAM), not connection errors.

## Acceptance criteria

- One test per rule.
