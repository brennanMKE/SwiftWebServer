# 0021 — Headers stored in a dictionary drop duplicates and allow duplicate Content-Length

| | |
|---|---|
| **Status** | open |
| **Module** | Semantics |
| **Platform** | macOS |
| **First seen** | 2026-09-12 |

## Description

Request and response headers are `[String: String]`. When parsing, repeated field lines overwrite each other (`HTTPRequest.swift:59-65`), and fields that differ only by case become separate keys. When serializing, header order is random, and `HTTPResponse.data` appends `Content-Length` even if the caller already supplied one (`HTTPResponse.swift:26-33`), which produces a duplicate header that some clients reject.

## Expected behavior

Header fields are an ordered collection with case-insensitive lookup that keeps duplicates, and `Content-Length` appears exactly once.

## Actual behavior

Duplicates are lost, order is random, and `Content-Length` can be duplicated.

## Notes

#0030 introduces `HTTPFields` for both HTTP/1.1 and HTTP/2. Fix this bug with that type, or with a minimal version of it.
