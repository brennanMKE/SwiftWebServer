# 0015 — Request paths are percent-decoded twice

| | |
|---|---|
| **Status** | open |
| **Module** | Security / StaticFiles |
| **Platform** | macOS |
| **First seen** | 2026-09-12 |

## Description

`URLComponents.path` (`HTTPRequest.swift:51`) is already percent-decoded, and `respond(to:)` decodes it again with `removingPercentEncoding` (`HTTPServer.swift:193`). A request for a file whose name contains `%` resolves to the wrong file. Double decoding is also a classic filter-bypass pattern: `%252e%252e` becomes `..` after two passes.

## Steps to reproduce

1. `echo hi > "Root/Public/100%25.txt"`
2. `curl -i http://localhost:8080/100%2525.txt`

## Expected behavior

200 with `hi`.

## Actual behavior

404, because the path is decoded twice to `100%.txt`.

## Notes

Decode exactly once, and do it before the block list and containment checks, so every security check sees the same path that is used to open the file. Reject paths that contain encoded `/` or NUL.
