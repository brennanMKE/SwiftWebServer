# 0033 — Parse HTTP/1.1 as an AsyncSequence of requests with keep-alive

| | |
|---|---|
| **Status** | open |

| **Platform** | macOS |
| **First seen** | 2026-09-12 |

## Description

Replace the single-shot parser with a codec that turns inbound bytes into an AsyncSequence of requests: `transport.inbound.http1Requests(limits:)`. Connections are reused for multiple sequential requests. This becomes the fallback path when HTTP/2 is not negotiated.

## Scope

- Incremental parsing across arbitrary read boundaries: request line, fields, `Content-Length` bodies, and `Transfer-Encoding: chunked` bodies exposed as the request's `HTTPBody`.
- Limits for request line, field section, and body size (#0011), and timeouts (#0012).
- Keep-alive per RFC 9112 §9.3. `Connection: close` and HTTP/1.0 behave correctly. Pipelined requests are answered in order.
- The response writer emits the status line and fields and applies `Content-Length` or chunked encoding.
- Leftover bytes after the preface check are replayed (needed by #0042).

## Acceptance criteria

- Tests cover a request split byte by byte, two pipelined requests, a chunked body, oversized headers (431), and an idle timeout.
- Regression tests from #0006 and #0007 pass.
