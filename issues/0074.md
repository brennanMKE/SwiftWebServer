## Description

The legacy server stores headers in `[String: String]`, which drops duplicates, allows duplicate `Content-Length` and does a linear case-insensitive Foundation scan (#0021). Replace it with ordered, duplicate-preserving fields indexed by small IDs for well-known names, plus protocol-agnostic method, status and message types shared by HTTP/1.1, HTTP/2 and HTTP/3.

## Scope

- `HTTPFields` (owned, for responses) and `HTTPFieldsView` (borrowed, for requests): parallel arrays of name ID, name range and value range over one byte arena; order and duplicates kept; storage reused with `removeAll(keepingCapacity:)`.
- Well-known header IDs resolved from a power-of-two table keyed by the FNV-1a hash from #0073 (at least `host`, `content-length`, `transfer-encoding`, `connection`, `te`, `expect`, `date`, `content-type`, `if-none-match`, `if-modified-since`, `range`, `accept-encoding`, `upgrade`, `sec-websocket-*`); unknown names keep their bytes.
- Lookup by ID is O(1) per field; `values(for:)` iterates duplicates; combined-value helper for list-valued fields.
- `HTTPMethod` enum with word-compare parsing of the standard methods and `.other(bytes)`; `HTTPStatus` with static, pre-rendered reason phrases and status lines.
- `HTTPRequest` and `HTTPResponse` shapes from ROADMAP §5.2 (body enum cases declared; streaming behaviour in #0081). `HTTPRequest` borrows per-connection storage and traps in debug builds on use after the handler returns (generation counter); `snapshot()` copies it out.
- Rule from #0021: more than one `Content-Length` with differing values is detectable so the parser can reject it.

## Acceptance criteria

- Tests: duplicate headers preserved in order; case-insensitive lookup of every well-known ID; unknown header names round-trip; two different `Content-Length` values are flagged; use-after-return traps in a debug-only test (exit test or documented manual check).
- `sws-bench fields` shows 0 allocations per request when filling and clearing a 10-header request repeatedly, and well-known lookup under 10 ns.

## Root cause

The legacy server models headers as `[String: String]` (drops duplicates, allows conflicting `Content-Length`, linear Foundation case-insensitive scan) and methods/statuses as Strings. There were no protocol-agnostic message types for HTTP/1.1, HTTP/2 and HTTP/3 to share.

## Fix

- `HTTPFieldName`: `UInt8` enum of 90 well-known names (HPACK + QPACK static-table names, framing/connection fields, `sec-websocket-*`, pseudo-headers) plus `.unknown`. Resolved through a 512-slot power-of-two table: slot = `(fnv1a &* 0x014C6DC7) >> 23`, chosen by search to be collision-free; candidates are confirmed by full-hash and byte compare. `lookup(hash:name:)` is the parser entry point that takes the hash computed during the name scan.
- `HTTPFieldIndex`: parallel arrays (ID, name `ByteView`, value `ByteView`) plus a 128-bit presence mask; `removeAll(keepingCapacity:)` reuses storage.
- `HTTPFieldCollection` protocol: one implementation of lookups for both field types — by ID, by name bytes (case-insensitive), `values(for:)`, list elements (quoted-string aware), `containsListElement`, `combinedValue(for:separator:into:)`, and `contentLength()` returning `.absent/.value/.invalid/.conflicting` (#0021).
- `HTTPRequestStorage` (per-connection, `@unchecked Sendable` class with `@exclusivity(unchecked)` properties) + `HTTPFieldsView` (borrowed, generation-checked with `assert`) for requests; `HTTPFields` (owned arena; well-known names stored as ID only) for responses.
- `HTTPMethod`: enum with `.other(Token)` where the token (≤ 24 tchar bytes) is stored inline in three `UInt64` lanes; standard methods matched by one word compare.
- `HTTPStatus`: code + optional custom reason; registered codes return a pre-rendered `HTTP/1.1 NNN Reason\r\n` `StaticString`, and the reason phrase is sliced from that literal.
- `HTTPRequest` (with `snapshot()`), `HTTPResponse`, `HTTPRequestBody` (`.empty` only, sources arrive in #0081), `HTTPResponseBody` (`.empty/.bytes/.stream/.file(FileRegion)/.tunnel`), `HTTPBodyWriter`, `HTTPHandler`, `HTTPMiddleware`, minimal `RequestContext` (fleshed out in #0083).
- `PseudoHeaderValidator`: value-type validator for HTTP/2 and HTTP/3 field sections (ordering, duplicates, required/forbidden pseudo-headers, CONNECT and extended CONNECT, `*` path, lowercase names, CR/LF/NUL and surrounding whitespace in values, connection-specific fields, `te: trailers`). #0047 and #0101 extend it.

## Gotchas

- Mutable stored properties of a class get dynamic exclusivity checks even in release; `HTTPRequestStorage` marks them `@exclusivity(unchecked)` (fill+clear went from ~545 ns to ~195 ns).
- Debug builds allocate heavily in the generic closure-based accessors (~147 allocations per refill), so the zero-allocation assertion runs only in release (`swift test -c release`). In release, LLVM also elides `malloc`/`free` pairs and stack-promotes classes, so the counter calibration uses an `@_optimize(none)` allocation.
- Adding a well-known name can collide in the table: `Table.init` traps and `tableIsCollisionFree` fails; choose a new odd `tableMultiplier` (random search, see the doc comment).
- `StaticString.withUTF8Buffer` is non-throwing, so APIs that hand out canonical names (`withName(at:)`) cannot use typed throws.
- Request names read back as the canonical lowercase name for well-known IDs and as received bytes for unknown names; HTTP/2/3 encoders must lowercase unknown names.
- `HTTPRequest.snapshot()` copies the head only; its body is `.empty`.
