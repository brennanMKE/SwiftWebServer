# 0074 — HTTPFields, HTTPMethod and HTTPStatus model messages without dictionaries or Strings

| | |
|---|---|
| **Status** | open |
| **Module** | HTTPCore |
| **Platform** | macOS |
| **First seen** | 2026-11-11 |

## Description

The legacy server stores headers in `[String: String]`, which drops duplicates, allows duplicate `Content-Length` and does a linear case-insensitive Foundation scan (#0021). Replace it with ordered, duplicate-preserving fields indexed by small IDs for well-known names, plus protocol-agnostic method, status and message types shared by HTTP/1.1, HTTP/2 and HTTP/3.

## Scope

- `HTTPFields` (owned, for responses) and `HTTPFieldsView` (borrowed, for requests): parallel arrays of name ID, name range and value range over one byte arena; order and duplicates kept; storage reused with `removeAll(keepingCapacity:)`.
- Well-known header IDs resolved from a power-of-two table keyed by the FNV-1a hash from #0073 (at least `host`, `content-length`, `transfer-encoding`, `connection`, `te`, `expect`, `date`, `content-type`, `if-none-match`, `if-modified-since`, `range`, `accept-encoding`, `upgrade`, `sec-websocket-*`); unknown names keep their bytes.
- Lookup by ID is O(1) per field; `values(for:)` iterates duplicates; combined-value helper for list-valued fields.
- `HTTPMethod` enum with word-compare parsing of the standard methods and `.other(bytes)`; `HTTPStatus` with static, pre-rendered reason phrases and status lines.
- `HTTPRequest` and `HTTPResponse` shapes from ROADMAP §5.2 (body enum cases declared; streaming behaviour in #0081). `HTTPRequest` borrows per-connection storage and traps in debug builds on use after the handler returns (generation counter); `snapshot()` copies it out.
- Rule from #0021: more than one `Content-Length` with differing values is detectable so the parser can reject it.

## Acceptance criteria

- Tests: duplicate headers preserved in order; case-insensitive lookup of every well-known ID; unknown header names round-trip; two different `Content-Length` values are flagged; use-after-return traps in a debug-only test (exit test or documented manual check).
- `sws-bench fields` shows 0 allocations per request when filling and clearing a 10-header request repeatedly, and well-known lookup under 10 ns.
