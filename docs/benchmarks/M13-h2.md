## Notes

- This is the first HTTP/2 load record, so there is no previous record to compare with.
- The nginx spread between runs is over 10% in the small-body case, so its numbers are for
  scale only. sws-bench answers from memory; nginx's `/big` reads a file from the page cache
  (HTTP/2 does not use sendfile in nginx).
- No run tripped an abuse limit (#0056): h2load opens 16 connections and sends 12,500 requests
  on each, below `maxStreamsPerConnection` (100,000), and returns credit at half a window, so no
  DATA frame falls below `smallDataFrameSize`.
- `HTTP2Tests.H2CurlTests` runs h2load as a smoke test (`h2loadRequestsAllSucceed`,
  `h2loadSmallWindowsDownloadWhole` with 16 KiB stream and 64 KiB connection windows) through
  `HTTPTestSupport.ChildProcess`, when `/opt/homebrew/bin/h2load` is installed.

- Client: oha 1.16.0, `-c 16`, loopback. Keep-alive cases run `-z 10s`; the no-keep-alive case

## Cleartext: h2c off against on (HTTP/1.1 clients)

`"http2": {"cleartext": false}` (the default) registers one protocol, so a cleartext connection
goes straight to HTTP/1.1. `"cleartext": true` registers `[HTTP2, HTTP1]`, so every cleartext
connection is sniffed (a read-ahead with a timeout task) and then served through
`PrefixedTransport`, which takes a lock on every receive (#0042 Gotchas).

| Case | Runs (req/s) | Median req/s | p50 | p99 |
|---|---|---:|---:|---:|
| keep-alive, h2c off | 80,066 · 91,576 · 90,055 · 79,521 · 79,773 · 81,279 · 90,078 | 81,279 | 168 µs | 607 µs |
| keep-alive, h2c on | 81,823 · 81,887 · 87,240 · 73,360 · 83,283 · 80,573 · 92,029 | 81,887 | 175 µs | 605 µs |
| no keep-alive, h2c off | 23,850 · 22,665 · 22,398 | 22,665 | 638 µs | 1.66 ms |
| no keep-alive, h2c on | 23,738 · 22,577 · 21,038 | 22,577 | 663 µs | 1.51 ms |

Paired keep-alive differences (on against off, same round): +2.2%, −10.6%, −3.1%, −7.7%,
+4.4%, −0.9%, +2.2%; median −0.9%. Without keep-alive (one sniff per request): −0.5%,
−0.4%, −6.1%; median −0.5%, with p50 4% higher. The sniff and replay cost is below the 5%
threshold and inside this run's noise, so there is no follow-up issue. A quieter machine
could still resolve a 1–3% difference; the default (cleartext off) pays none of it.

## Notes

- oha's HTTP/2 mode sends one request at a time per connection (16 streams in flight in all),
  so these HTTP/2 numbers measure latency per exchange, not multiplexing. The h2load records
  above (`-m 10`) are the throughput numbers for HTTP/2.
- HTTPS with HTTP/1.1 and with HTTP/2 are within noise of each other at this concurrency; TLS
  (Network.framework) dominates both.
